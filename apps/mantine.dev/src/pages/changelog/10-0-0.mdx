## @mantine/data-grid package

New [@mantine/data-grid](/data-grid/getting-started) package provides a fully featured data grid
component built on top of [TanStack Table v9](https://tanstack.com/table) and
[TanStack Virtual](https://tanstack.com/virtual) with compound components and full Styles API
support. Supported features:

- Sorting, filtering, global search and pagination, with server-side mode for all of them
- Column resizing, pinning, visibility toggling, reordering and a column menu
- Row selection, spreadsheet-style cell selection and cell spanning
- Row expansion with detail panels, grouping with aggregation and tree data
- Inline cell and row editing with validation
- Row virtualization for large datasets
- State persistence to localStorage, sessionStorage or custom storage
- Compound components for custom layouts: toolbar, global filter, export button, selection bar and footer
- Loading and empty states, list view for narrow screens
- Semantic `table` or ARIA grid roles with keyboard navigation

## use-form engine and uncontrolled mode

`useForm` is now uncontrolled by default. When the user types, only the input rerenders, not the
component that calls `useForm`. `form.key()` is no longer needed and has been removed:

```tsx
import { TextInput } from '@mantine/core';
import { useForm } from '@mantine/form';

function Demo() {
  const form = useForm({ initialValues: { email: '' } });
  return <TextInput label="Email" {...form.getInputProps('email')} />;
}
```

New `form.useDirty` and `form.useTouched` hooks subscribe a component to dirty and touched state.
Custom inputs subscribe to a field with the new [use-form-field](/hooks/use-form-field) hook.
See [uncontrolled mode](/form/uncontrolled) for details.

## Reusable form fields

New `form.getField('path')` returns a field object with the same type as `useField`.
A component that accepts it works in any form and with `useField`, see [reusable fields](/form/reusable-fields/):

```tsx
import { TextInput } from '@mantine/core';
import { useField, useForm, UseFieldReturnType } from '@mantine/form';

function EmailField({ field }: { field: UseFieldReturnType<string> }) {
  return <TextInput label="Email" {...field.getInputProps()} />;
}

function Demo() {
  const signup = useForm({ initialValues: { email: '' } });
  const checkout = useForm({ initialValues: { contact: { email: '' } } });
  const newsletter = useField({ initialValue: '' });

  return (
    <>
      <EmailField field={signup.getField('email')} />
      <EmailField field={checkout.getField('contact.email')} />
      <EmailField field={newsletter} />
    </>
  );
}
```

## OKLCH default palettes

Default colors are regenerated in the OKLCH color space. Shades with the same index now look
equally bright in every color, so filled components look consistent across colors.

Color names, the number of shades and `primaryShade` are unchanged. `--mantine-color-*` CSS
variables now contain `oklch()` values, see the [migration guide](/guides/9x-to-10x) if you parse them.

## autoContrast enabled by default

`theme.autoContrast` is now `true` by default: filled components pick black or white text to match
their background color. Set `autoContrast: false` in the theme to restore the previous behavior.

## Neutral color ladder

New `--mantine-color-neutral-0` to `--mantine-color-neutral-9` variables adapt to the color scheme.
Use them in custom CSS instead of separate `gray` and `dark` shades:

```css
.card {
  background-color: var(--mantine-color-neutral-1);
  border: 1px solid var(--mantine-color-neutral-4);
}
```

## Surface component

New [Surface](/core/surface) component replaces `Paper`. Nested surfaces step up one level
automatically, so elevation is visible in dark mode. `Paper` is deprecated and will be removed in 11.0:

```tsx
import { Surface } from '@mantine/core';

function Demo() {
  return (
    <Surface p="md" withBorder>
      Outer surface
      <Surface p="md">Inner surface, one level higher</Surface>
    </Surface>
  );
}
```

Use the `surfaces` theme key to change surface colors for each color scheme:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  surfaces: {
    dark: {
      panel: '#101113',
    },
  },
});
```

## Dropdowns render on the page surface

Dropdowns of `Popover`, `Menu`, `HoverCard` and `Combobox`-based components now use the page
background, like `Modal` and `Drawer`. In dark mode they are darker than before and are separated
from the content with a border and a shadow.

## Sunken surfaces, code surfaces and control tracks

`SegmentedControl`, `contained` `Tabs` and `ScrollArea` scrollbars now share the sunken surface
color. `Code`, `Kbd`, `CodeHighlight` and `JsonViewer` share the muted surface color.
Tracks of `Switch`, `Slider` and `Progress` use the new `--mantine-color-track` variable.

## Focus ring color variable

Focus rings now use the new `--mantine-color-focus-ring` variable. In dark mode it is lighter than
the primary color, so the ring stays visible. Override it to change focus rings of all components:

```css
[data-mantine-color-scheme='dark'] {
  --mantine-color-focus-ring: var(--mantine-color-lime-4);
}
```

## Dark neutral flavors

`darkColors`, `darkColdColors`, `darkWarmColors` and `darkTintedColors` change the tone of the dark
color scheme. Assign one of them to `theme.colors.dark`:

```tsx
import { createTheme, darkWarmColors } from '@mantine/core';

const theme = createTheme({
  colors: {
    dark: darkWarmColors,
  },
});
```

## tintColors utility

New `tintColors` function mixes a color into every shade of the dark palette:

```tsx
import { createTheme, darkColors, tintColors } from '@mantine/core';

const theme = createTheme({
  colors: {
    dark: tintColors(darkColors, '#5c7cfa', 0.15),
  },
});
```

## OKLCH colors generator

`generateColors` from `@mantine/colors-generator` now returns OKLCH colors. New
`generateColorFormats` function returns the palette in hex, rgb, hsl and oklch:

```tsx
import { generateColors } from '@mantine/colors-generator';

const theme = createTheme({
  colors: {
    brand: generateColors('#375EAC'),
  },
});
```

## Other changes

- [Affix](/core/affix) now supports `withSafeArea` prop to keep the content clear of the device notch and home indicator.
- [Alert](/core/alert) now supports `size` and `closeButtonProps` props.
- [AngleSlider](/core/angle-slider) now supports `largeStep` and `readOnly` props and `PageUp`/`PageDown` keys.
- [Avatar.Group](/core/avatar) now supports `max` prop: avatars that do not fit are replaced with a `+N` counter.
- [Badge](/core/badge) with `variant="dot"` no longer renders `leftSection`.
- [Breadcrumbs](/core/breadcrumbs) and [Pagination](/core/pagination) root elements are now `nav` landmarks.
- [ColorPicker](/core/color-picker) now follows `theme.defaultRadius`.
- [Drawer](/core/drawer) now supports `fullScreen` prop.
- [MultiSelect](/core/multi-select#max-displayed-values) and [TagsInput](/core/tags-input#max-displayed-values) now support `maxDisplayedValues` prop: extra values collapse into a `+N more` pill.
- [NavLink](/core/nav-link) with nested links and without `href` is now rendered as a `button` element.
- [PasswordInput](/core/password-input) visibility toggle icon is now smaller.
- [Select](/core/select#scrollable-dropdown) and other `Combobox`-based components now support `scrollBehavior="smooth"` for keyboard navigation.
- [Stepper.Step](/core/stepper#wrapping-stepperstep) and [Timeline.Item](/core/timeline#wrapping-timelineitem) can now be wrapped in other components.
- [Timeline.Item](/core/timeline) now supports `active` and `lineActive` props.
- [Tooltip](/core/tooltip) now opens on keyboard focus, set `events={{ hover: true, focus: false, touch: false }}` to restore the previous behavior.
- [Combobox.Target](/core/combobox) now sets `role="combobox"` and `aria-expanded`, set `withExpandedAttribute={false}` to restore the previous behavior.
- [LoadingOverlay](/core/loading-overlay) now announces the loading state to screen readers, change the text with `loadingLabel` prop.
- [Pill](/core/pill) remove button now has `aria-label="Remove"` by default.
- Inputs with `error` prop now have a lighter placeholder, so an empty invalid input does not look like it has a value.
- `Tree` now receives its store with the `store` prop, see the [migration guide](/guides/9x-to-10x).
