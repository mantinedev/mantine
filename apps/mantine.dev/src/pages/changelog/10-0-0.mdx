## use-form engine and uncontrolled mode

`useForm` is now uncontrolled by default. Typing rerenders only the input, not the whole form,
and `form.key()` is no longer needed:

```tsx
import { TextInput } from '@mantine/core';
import { useForm } from '@mantine/form';

function Demo() {
  const form = useForm({ initialValues: { email: '' } });
  return <TextInput label="Email" {...form.getInputProps('email')} />;
}
```

New `form.useDirty` and `form.useTouched` hooks subscribe a component to dirty and touched state,
and custom inputs subscribe to a field with the `useFormField` hook.
See [uncontrolled mode](/form/uncontrolled) for details.

## Reusable form fields

New `form.getField('path')` returns a field object with the same type as `useField`.
A component that accepts it works with any form, see [reusable fields](/form/reusable-fields/):

```tsx
import { TextInput } from '@mantine/core';
import { useField, useForm, UseFieldReturnType } from '@mantine/form';

function EmailField({ field }: { field: UseFieldReturnType<string> }) {
  return <TextInput label="Email" {...field.getInputProps()} />;
}

function Demo() {
  const signup = useForm({ initialValues: { email: '' } });
  const checkout = useForm({ initialValues: { contact: { email: '' } } });
  const newsletter = useField({ initialValue: '' });

  return (
    <>
      <EmailField field={signup.getField('email')} />
      <EmailField field={checkout.getField('contact.email')} />
      <EmailField field={newsletter} />
    </>
  );
}
```

## Conditional validation

New `when` validator runs a rule only when the condition returns `true`.
Use it for fields that are required depending on another field, see [validators](/form/validators/#when):

```tsx
import { isNotEmpty, useForm, when } from '@mantine/form';

const form = useForm({
  initialValues: { isCompany: false, companyName: '' },
  validate: {
    companyName: when(
      (values) => values.isCompany,
      isNotEmpty('Company name is required')
    ),
  },
});
```

## Surface component

New [Surface](/core/surface) component replaces `Paper`, which is deprecated and will be removed in 11.0.
Nested surfaces step up one level automatically, so elevation is visible in dark mode:

```tsx
import { Surface } from '@mantine/core';

function Demo() {
  return (
    <Surface p="md" withBorder>
      Outer surface
      <Surface p="md">Inner surface, one level higher</Surface>
    </Surface>
  );
}
```

Use the `surfaces` theme key to change surface colors for each color scheme:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  surfaces: {
    dark: {
      panel: '#101113',
    },
  },
});
```

## Inputs use the page surface in dark mode

Inputs, checkboxes, radios, `Dropzone` and `RichTextEditor` now share the `--mantine-color-surface-input`
variable, which is the page color in dark mode. Fields stay visible inside [Surface](/core/surface) cards
and the editor matches the other inputs. Change it with the `surfaces` theme key:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  surfaces: {
    dark: {
      input: 'var(--mantine-color-dark-8)',
    },
  },
});
```

## Dropdowns render on the page surface

Dropdowns of `Popover`, `Menu` and `Combobox` based components now use the page background, like `Modal`.
In dark mode they are darker than before and are separated from the content with a border and a shadow.

## Sunken surfaces, code surfaces and control tracks

Segmented controls, contained tabs and scrollbars now share one sunken surface color.
Code elements share one muted surface color, and tracks of switches, sliders and progress bars
use the new `--mantine-color-track` variable.

## Write to storage without rerender

New `writeLocalStorageValue` and `removeLocalStorageValue` functions update storage and every
`useLocalStorage` hook with the same key without rerendering the component that calls them.
See [use-local-storage](/hooks/use-local-storage#write-value-without-rerender):

```tsx
import { useLocalStorage, writeLocalStorageValue } from '@mantine/hooks';

function DraftStatus() {
  const [savedAt] = useLocalStorage<string | null>({ key: 'draft-saved-at', defaultValue: null });
  return <p>{savedAt ? `Draft saved at ${savedAt}` : 'No draft saved'}</p>;
}

function Editor() {
  // Editor does not rerender when the draft is saved
  const saveDraft = () =>
    writeLocalStorageValue({ key: 'draft-saved-at', value: new Date().toLocaleTimeString() });

  return (
    <>
      <textarea onBlur={saveDraft} />
      <DraftStatus />
    </>
  );
}
```

## Other changes

- [Affix](/core/affix) now supports `withSafeArea` prop to keep the content clear of the device notch.
- [Alert](/core/alert) now supports `size` and `closeButtonProps` props.
- [AngleSlider](/core/angle-slider) now supports `largeStep` and `readOnly` props and `PageUp`/`PageDown` keys.
- [Avatar.Group](/core/avatar) now supports `max` prop: avatars that do not fit are replaced with a `+N` counter.
- [Badge](/core/badge) with `variant="dot"` no longer renders `leftSection`.
- [Breadcrumbs](/core/breadcrumbs) and [Pagination](/core/pagination) root elements are now `nav` landmarks.
- [ColorPicker](/core/color-picker) now follows `theme.defaultRadius`.
- [Drawer](/core/drawer) now supports `fullScreen` prop.
- [Input.Wrapper](/core/input#withblockchildren) now supports `withBlockChildren` prop to render non-input children with the same spacing as inputs.
- [MultiSelect](/core/multi-select#max-displayed-values) and [TagsInput](/core/tags-input#max-displayed-values) now support `maxDisplayedValues` prop.
- [NavLink](/core/nav-link) with nested links and without `href` is now rendered as a `button` element.
- [PasswordInput](/core/password-input) visibility toggle icon is now smaller.
- [Select](/core/select#scrollable-dropdown) and other `Combobox`-based components now support `scrollBehavior="smooth"` for keyboard navigation.
- [Stepper.Step](/core/stepper#wrapping-stepperstep) and [Timeline.Item](/core/timeline#wrapping-timelineitem) can now be wrapped in other components.
- [Timeline.Item](/core/timeline) now supports `active` and `lineActive` props.
- [Tooltip](/core/tooltip) now opens on keyboard focus, set `events={{ hover: true, focus: false, touch: false }}` to restore the previous behavior.
- [Combobox.Target](/core/combobox) now sets `role="combobox"` and `aria-expanded`, set `withExpandedAttribute={false}` to restore the previous behavior.
- [LoadingOverlay](/core/loading-overlay) now announces the loading state to screen readers, change the text with `loadingLabel` prop.
- [Pill](/core/pill) remove button now has `aria-label="Remove"` by default.
- `Tree` now receives its store with the `store` prop, see the [migration guide](/guides/9x-to-10x).
- [DatePickerInput](/dates/date-picker-input#multiple-dates) and the other picker inputs (month, year, week, quarter) with `type="multiple"` now support `valueDisplay="pills"` to render a removable pill per selected value.
- [DatesProvider](/dates/getting-started#consistent-weeks) `consistentWeeks` is now `true` by default – every month has 6 weeks, set `consistentWeeks: false` to restore the previous behavior.
- New [Combobox examples](/combobox/MultiSelectSelectAll): select all in multiselect, category filter in the dropdown header, option details panel and mobile bottom sheet.
