## @mantine/data-grid package

New [@mantine/data-grid](/data-grid/getting-started) package provides a fully featured data grid
component built on top of [TanStack Table v9](https://tanstack.com/table) and
[TanStack Virtual](https://tanstack.com/virtual) with compound components and full Styles API
support. Supported features:

- Sorting, filtering, global search and pagination, with server-side mode for all of them
- Column resizing, pinning, visibility toggling, reordering and a column menu
- Row selection, spreadsheet-style cell selection and cell spanning
- Row expansion with detail panels, grouping with aggregation and tree data
- Inline cell and row editing with validation
- Row virtualization for large datasets
- State persistence to localStorage, sessionStorage or custom storage
- Compound components for custom layouts: toolbar, global filter, export button, selection bar and footer
- Loading and empty states, list view for narrow screens
- Semantic `table` or ARIA grid roles with keyboard navigation

## Component controllers and stores

Components that own state can now be driven with a hook. Call `use<Component>` in your component
and pass the result to the component: a controller with the `controller` prop, a store with the
`store` prop. The [Controllers and stores](/guides/controllers) guide explains the pattern, each
component documents its own actions and queries.

A controller adds actions and queries to a component that you use as is, for example `expandAll`
and `collapseAll` on `Accordion`, which props cannot express. Adopting a controller is always
additive, the component keeps working with `value`, `defaultValue` and `onChange` as before:

<Demo data={AccordionDemos.controller} />

A store is a building block for your own component. For example, `useSelect` reuses the value,
search and dropdown handling of `Select` to build a select that can create new options:

## Automatic Modal and Drawer stacking

New `theme.overlayStack` option stacks all [Modal](/core/modal/#shared-stack) and
[Drawer](/core/drawer/#shared-stack) components automatically – no `Modal.Stack`/`Drawer.Stack`
wrappers or `stackId` props required:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  overlayStack: true,
});
```

<Demo data={ModalDemos.overlayStack} />

All modals join one shared `Modal.Stack` and all drawers join one shared `Drawer.Stack`. Modals and
drawers are stacked visually in separate stacks, but z-index, focus trap and `Escape` key handling
always follow the topmost opened modal or drawer. New `useModalStackContext` and
`useDrawerStackContext` hooks provide access to the shared stacks.

## OKLCH default palettes

All 14 built-in color palettes (`dark`, `gray`, `red`, `pink`, `grape`, `violet`, `indigo`, `blue`,
`cyan`, `teal`, `green`, `lime`, `yellow`, `orange`) have been re-derived in the OKLCH color space.
The new palettes use a **shared perceptual-lightness ramp**: every color at index `N` has the same
perceived brightness regardless of hue, so filled buttons, badges, and other colored controls look
visually consistent across all hues. Warm and bright hues (yellow, orange, lime, green) are lifted on
a separate ramp to compensate for the Abney effect.

The number of shades (10), the color names, and the `primaryShade` default (`{ light: 6, dark: 7 }`)
are unchanged. All default shades remain within the sRGB gamut.

`--mantine-color-*` CSS variables are now emitted as `oklch(L C H)` strings. Code that reads and
parses these variables as hex or RGB must be updated. See the [9.x → 10.x migration guide](/guides/9x-to-10x)
for details.

## autoContrast enabled by default

`theme.autoContrast` now defaults to `true`. Filled controls automatically pick black or white text
based on the luminance of their background color (threshold `0.2`), so light shades used as a filled
color will switch to dark text without any extra configuration.

The following 22 components are affected: `Button`, `ActionIcon`, `ActionIconGroupSection`, `Badge`,
`ThemeIcon`, `Alert`, `Avatar`, `Chip`, `NavLink`, `TableOfContents`, `Toggle`, `Tooltip`, `Tabs`,
`Pagination`, `Radio`, `RadioIndicator`, `Checkbox`, `CheckboxIndicator`, `Indicator`, `Progress`,
`Stepper`, `SegmentedControl`, `Timeline`, and `Toolbar`/`ToolbarToggle`/`ToolbarToggleItem`.

To restore the v9 behaviour set `autoContrast: false` in the theme, or use the one-line v9 opt-out
described in the migration guide.

## Surface component

A new [Surface](/core/surface) component replaces `Paper` as the depth-aware background primitive. `Surface` has
3 levels – `0` (page), `1` (panel, the default for a standalone `Surface`), and `2` (panel-2) – and
in dark mode each level is one shade lighter, giving your UI natural elevation layers. In light mode
surfaces are near-flat and rely on shadows and borders instead of tone. Two separate tokens (not
`Surface` levels) cover non-container backgrounds: `--mantine-color-surface-sunken` for wells and
`--mantine-color-surface-muted` for code and inset content.

`Surface` is a strict superset of `Paper` (`shadow`, `radius`, `withBorder`, padding, polymorphic
`component` prop) and can be used as a drop-in replacement. `Paper` is deprecated in v10 and will be
removed in v11.

```tsx
import { Surface } from '@mantine/core';

// Manual level
function Demo() {
  return <Surface level={2} p="md">Content on elevation level 2</Surface>;
}

// Automatic depth stepping, on by default (each nested Surface steps up one level, clamped at level 2)
function Demo() {
  return (
    <Surface p="md">
      Outer surface
      <Surface p="md">
        Inner surface – one level higher
      </Surface>
    </Surface>
  );
}
```

`level` also accepts a relative string, `"+1"` or `"-1"`, which steps up or down from the parent
surface's level instead of setting an absolute value. Like an absolute `level`, a relative `level`
always overrides `autoDepth`, and both forms clamp to the `0`–`2` range.

Surface backgrounds can be overridden per color scheme with the `surfaces` theme key, without
touching CSS variables directly:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  surfaces: {
    dark: {
      panel: '#101113',
    },
  },
});
```

Each scheme (`light`/`dark`) accepts `page`, `panel`, `panel2`, `sunken`, and `muted` keys, matching
the five surface tokens documented above.

## Dropdowns render on the page surface

Floating dropdowns – `Popover`, `Menu`, `HoverCard`, and all `Combobox`-based components such as
`Select` and `Autocomplete` – now use `--mantine-color-surface-page` as their background, matching
`Modal` and `Drawer`. In dark mode dropdowns are now `dark-7` instead of `dark-6`, separated from
surrounding content by border and shadow; light mode is visually unchanged. Overriding
`surfaces.page` in the theme moves modals and dropdowns together with the page background.

## Sunken surfaces, code surfaces and control tracks

Wells share the `--mantine-color-surface-sunken` token: the `SegmentedControl` root, the `Tabs`
`contained` list, and `ScrollArea` scrollbar backgrounds. In dark mode these are tonally sunken
below the page (`dark-9`); in light mode they unify on `gray-1`. A well always holds a raised child
(the active segment or tab, drawn on `--mantine-color-surface-panel-2`), which is what the deep
dark value buys.

Code and inset content use `--mantine-color-surface-muted` instead: `Code`, `Kbd`, `CodeHighlight`,
`JsonViewer`, and `Typography` `pre`/`code`/`kbd`. It is `gray-0` in light mode – one light step
off the page – and `dark-5` in dark mode, two steps *above* the page, so a code block reads as
raised rather than as a hole punched into the page, and keeps its edge inside a `Card` or a
level-1 `Surface`.

Control tracks are a third role: `Switch`, `Slider`, `Progress`, `RingProgress`, and
`SemiCircleProgress` share the `--mantine-color-track` role variable, anchored to the border tone
(`gray-3` / `dark-4`) so the unfilled part of a control reads as a rail rather than a hole.

Overriding `surfaces.sunken` or `surfaces.muted` in the theme (or the tokens themselves) restyles
each group together; override `--mantine-color-track` to restyle every control track at once.

## Focus ring color variable

Focus rings are now drawn with a dedicated `--mantine-color-focus-ring` variable instead of
`--mantine-primary-color-filled`. It covers the `.mantine-focus-auto` / `.mantine-focus-always`
outline, the focused `Input` border, and every component that draws its own ring (`Switch`, `Chip`,
`Pill`, `Rating`, `Tree`, `AngleSlider`, `ColorPicker`, `ColorWheel`, `Editable`, `Timer`,
`Splitter`, `SegmentedControl`, charts, `DataGrid`, `CalendarHeader`, `EmojiPicker`, `JsonViewer`).

The variable follows `theme.primaryColor`, and its light value is unchanged (`blue-6` by default).
In dark mode it resolves to shade 5 rather than `primaryShade.dark` (shade 7), so the ring stays
legible against the darker v10 backgrounds. Override it to restyle focus rings across the entire
application without affecting filled buttons:

```css
[data-mantine-color-scheme='dark'] {
  --mantine-color-focus-ring: var(--mantine-color-lime-4);
}
```

## Disabled state opacity

All components now render their disabled state as a reduced-opacity version of their normal
appearance instead of switching to flat neutral colors. A disabled filled `Button` stays blue, a
checked disabled `Checkbox` keeps its accent color, and every other component follows the same
rule – only faded.

The opacity is controlled by a single theme option, `theme.disabledOpacity` (`0.5` by default),
exposed as the `--mantine-disabled-opacity` CSS variable. Override it globally in your theme, or
per subtree and color scheme with plain CSS.

## tintColors utility

A new `tintColors` function mixes a color into every shade of a `MantineColorsTuple`, useful for
building a custom-tinted dark ramp without hand-editing 10 shades. It targets the **dark** ramp –
tinting light neutrals forces surfaces darker and breaks the flat light look, so keep tinting to
dark:

```tsx
import { tintColors, darkColors, createTheme } from '@mantine/core';

const theme = createTheme({
  colors: {
    dark: tintColors(darkColors, '#5c7cfa', 0.15),
  },
});
```

`strength` (default `0.1`) controls how much of the tint is mixed in. Middle shades of the tuple
receive proportionally more tint than the shades near either end of the ramp.

`tintColors` returns CSS `color-mix(in oklab, ...)` strings that are resolved by the browser, not
concrete color values – the result cannot be fed into functions that expect a resolved color (such
as `darken`), and it appears as a `color-mix(...)` expression, not a hex/rgb value, in computed
styles.

## OKLCH colors generator

`@mantine/colors-generator` has been updated to output OKLCH color palettes. The `generateColors`
function still returns a `MantineColorsTuple` (now containing `oklch(...)` strings) so existing
usage is unchanged:

```tsx
import { generateColors } from '@mantine/colors-generator';

const theme = createTheme({
  colors: {
    brand: generateColors('#375EAC'), // returns MantineColorsTuple of oklch strings
  },
});
```

A new `generateColorFormats` function is also available when you need the full palette in multiple
formats (oklch, hex, rgb, hsl) along with the detected base color index.

## Other changes

- [Affix](/core/affix) now supports `withSafeArea` prop – when it is set, `env(safe-area-inset-*)` values are added to the `position` offsets, so the affixed content is not covered by the device notch or the home indicator.
- [Alert](/core/alert) now supports `closeButtonProps` and sets `Close` as the default close button `aria-label`.
- [AngleSlider](/core/angle-slider) now supports `largeStep` prop and `PageUp`/`PageDown`/`Shift + Arrow` keyboard interactions, a `readOnly` prop, and sets `aria-valuetext`, `aria-disabled` and `aria-readonly` attributes. Keyboard interactions now always produce values that are on the same grid as pointer interactions: with `step={5}`, `ArrowLeft` at `0` sets the value to `355` instead of `359`. `onMouseDown` and `onTouchStart` props are now forwarded to the root element – previously they were silently ignored.
- [Avatar.Group](/core/avatar) now supports `max`, `total` and `renderOverflow` props – children that do not fit into `max` are replaced with a `+N` counter.
- [Badge](/core/badge) no longer renders `leftSection` when `variant="dot"` is used – the dot indicator occupies the same slot and the two collided in the grid layout.
- [Breadcrumbs](/core/breadcrumbs) root element is now a `nav` landmark with a default `aria-label="Breadcrumbs"`, and separators are rendered with `aria-hidden` so that they are not announced by screen readers.
- [Alert](/core/alert) now supports the `size` prop
- [ColorPicker](/core/color-picker) saturation picker, sliders, preview swatch and color swatches now follow `theme.defaultRadius`
- [Stepper.Step](/core/stepper#wrapping-stepperstep) can now be wrapped in another component – the step index is passed by forwarding the props the wrapper receives or declared with the `step` prop.
- [Timeline.Item](/core/timeline#wrapping-timelineitem) can now be wrapped in another component – the item index is passed by forwarding the props the wrapper receives or declared with the new `index` prop. New `active` and `lineActive` props allow an item to be active while the line after it is not.
