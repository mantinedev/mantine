## New @mantine/data-grid package

New [`@mantine/data-grid`](/data-grid/getting-started) package provides a fully-featured data grid
component built on top of [TanStack Table v9](https://tanstack.com/table) and
[TanStack Virtual](https://tanstack.com/virtual). It fills the gap left by community libraries with
first-party Mantine integration, compound component architecture, and full Styles API support.

Key features:

- Sorting (single and multi-column), column and global filtering, pagination
- Column resizing, pinning, visibility toggling, and drag-and-drop reordering
- Row selection with checkboxes and Shift+click range select
- Spreadsheet-style cell selection with drag, Shift-extend and keyboard navigation
- Cell spanning across rows and columns
- Row expansion with detail panels
- Row virtualization for 100k+ rows via `@tanstack/react-virtual`
- Inline editing (cell and row modes) with validation
- Grouping and aggregation with built-in functions
- Server-side mode for sorting, filtering, and pagination
- State persistence to localStorage, sessionStorage, or custom storage
- Compound components for custom layouts (Toolbar, Table, Pagination, StatusBar)
- Full accessibility: semantic `<table>` or ARIA grid roles with keyboard navigation

[DataGrid](/data-grid/data-grid) renders a customizable data grid with all features enabled through
`with*` boolean props:

## Modal.Footer and Drawer.Footer

compound components to render a footer with actions. By default the footer stays pinned to the

## Modal and Drawer sticky header and footer

[Modal](/core/modal) and [Drawer](/core/drawer) now support the `stickyHeader` and `stickyFooter`
props (both default to `true`). When enabled, the header stays pinned to the top and the footer
stays pinned to the bottom while the body scrolls between them. Set either to `false` to make that
section scroll away with the body content.

[Modal.Stack](/core/modal/#modalstack) and [Drawer.Stack](/core/drawer/#drawerstack) have been
reworked – all opened stacked items now stay mounted and visible with a stacked depth effect
instead of hiding items below the top one. The new `maxDepth` prop (default `5`) controls how many
stacked items are visible behind the top one at the same time.

## Shared Modal.Stack and Drawer.Stack

New `theme.overlayStack` option makes all [Modal](/core/modal/#shared-stack) and
[Drawer](/core/drawer/#shared-stack) components in the application a part of the shared
`Modal.Stack` and `Drawer.Stack` – modals and drawers are stacked automatically without
`Modal.Stack`/`Drawer.Stack` wrappers and `stackId` props. New `useModalStackContext` and
`useDrawerStackContext` hooks provide access to the shared stacks:

```tsx

const theme = createTheme({
  overlayStack: true,
});
```

## Blockquote redesign

[Blockquote](/core/blockquote) has a new look. The tinted background, rounded corners and the icon
floating over the top left corner are gone. The quote is set in `lg` text next to a `3px` accent line,

## OKLCH default palettes

All 14 built-in color palettes (`dark`, `gray`, `red`, `pink`, `grape`, `violet`, `indigo`, `blue`,
`cyan`, `teal`, `green`, `lime`, `yellow`, `orange`) have been re-derived in the OKLCH color space.
The new palettes use a **shared perceptual-lightness ramp**: every color at index `N` has the same
perceived brightness regardless of hue, so filled buttons, badges, and other colored controls look
visually consistent across all hues. Warm and bright hues (yellow, orange, lime, green) are lifted on
a separate ramp to compensate for the Abney effect.

The number of shades (10), the color names, and the `primaryShade` default (`{ light: 6, dark: 7 }`)
are unchanged. All default shades remain within the sRGB gamut.

`--mantine-color-*` CSS variables are now emitted as `oklch(L C H)` strings. Code that reads and
parses these variables as hex or RGB must be updated. See the [9.x → 10.x migration guide](/guides/9x-to-10x)
for details.

## autoContrast enabled by default

`theme.autoContrast` now defaults to `true`. Filled controls automatically pick black or white text
based on the luminance of their background color (threshold `0.2`), so light shades used as a filled
color will switch to dark text without any extra configuration.

The following 22 components are affected: `Button`, `ActionIcon`, `ActionIconGroupSection`, `Badge`,
`ThemeIcon`, `Alert`, `Avatar`, `Chip`, `NavLink`, `TableOfContents`, `Toggle`, `Tooltip`, `Tabs`,
`Pagination`, `Radio`, `RadioIndicator`, `Checkbox`, `CheckboxIndicator`, `Indicator`, `Progress`,
`Stepper`, `SegmentedControl`, `Timeline`, and `Toolbar`/`ToolbarToggle`/`ToolbarToggleItem`.

To restore the v9 behaviour set `autoContrast: false` in the theme, or use the one-line v9 opt-out
described in the migration guide.

## Surface component

A new [Surface](/core/surface) component replaces `Paper` as the depth-aware background primitive. `Surface` has
3 levels – `0` (page), `1` (panel, the default for a standalone `Surface`), and `2` (panel-2) – and
in dark mode each level is one shade lighter, giving your UI natural elevation layers. In light mode
surfaces are near-flat and rely on shadows and borders instead of tone. A separate
`--mantine-color-surface-sunken` token (not a `Surface` level) covers inset elements like code
blocks and slider tracks.

`Surface` is a strict superset of `Paper` (`shadow`, `radius`, `withBorder`, padding, polymorphic
`component` prop) and can be used as a drop-in replacement. `Paper` is deprecated in v10 and will be
removed in v11.

```tsx
import { Surface } from '@mantine/core';

// Manual level
function Demo() {
  return <Surface level={2} p="md">Content on elevation level 2</Surface>;
}

// Automatic depth stepping, on by default (each nested Surface steps up one level, clamped at level 2)
function Demo() {
  return (
    <Surface p="md">
      Outer surface
      <Surface p="md">
        Inner surface – one level higher
      </Surface>
    </Surface>
  );
}
```

`level` also accepts a relative string, `"+1"` or `"-1"`, which steps up or down from the parent
surface's level instead of setting an absolute value. Like an absolute `level`, a relative `level`
always overrides `autoDepth`, and both forms clamp to the `0`–`2` range.

Surface backgrounds can be overridden per color scheme with the `surfaces` theme key, without
touching CSS variables directly:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  surfaces: {
    dark: {
      panel: '#101113',
    },
  },
});
```

Each scheme (`light`/`dark`) accepts `page`, `panel`, `panel2`, and `sunken` keys, matching the four
surface tokens documented above.

## Dropdowns render on the page surface

Floating dropdowns – `Popover`, `Menu`, `HoverCard`, and all `Combobox`-based components such as
`Select` and `Autocomplete` – now use `--mantine-color-surface-page` as their background, matching
`Modal` and `Drawer`. In dark mode dropdowns are now `dark-7` instead of `dark-6`, separated from
surrounding content by border and shadow; light mode is visually unchanged. Overriding
`surfaces.page` in the theme moves modals and dropdowns together with the page background.

## Sunken surfaces and control tracks

Inset elements now share the `--mantine-color-surface-sunken` token: `SegmentedControl` root,
`Code`, `Kbd`, and `ScrollArea` scrollbar background. In dark mode these elements are now tonally
sunken below the page (`dark-9`); in light mode they unify on `gray-1`. Control tracks are a
separate role: `Switch`, `Slider`, `Progress`, `RingProgress`, and `SemiCircleProgress` share the
`--mantine-color-track` role variable, anchored to the border tone (`gray-3` / `dark-4`) so the
unfilled part of a control reads as a rail rather than a hole. Overriding `surfaces.sunken` in the theme (or the
token itself) restyles all inset elements together; override `--mantine-color-track` to restyle every control
track at once.

## Disabled state opacity

All components now render their disabled state as a reduced-opacity version of their normal
appearance instead of switching to flat neutral colors. A disabled filled `Button` stays blue, a
checked disabled `Checkbox` keeps its accent color, and every other component follows the same
rule – only faded.

The opacity is controlled by a single theme option, `theme.disabledOpacity` (`0.5` by default),
exposed as the `--mantine-disabled-opacity` CSS variable. Override it globally in your theme, or
per subtree and color scheme with plain CSS.

## tintColors utility

A new `tintColors` function mixes a color into every shade of a `MantineColorsTuple`, useful for
building a custom-tinted dark ramp without hand-editing 10 shades. It targets the **dark** ramp –
tinting light neutrals forces surfaces darker and breaks the flat light look, so keep tinting to
dark:

```tsx
import { tintColors, darkColors, createTheme } from '@mantine/core';

const theme = createTheme({
  colors: {
    dark: tintColors(darkColors, '#5c7cfa', 0.15),
  },
});
```

`strength` (default `0.1`) controls how much of the tint is mixed in. Middle shades of the tuple
receive proportionally more tint than the shades near either end of the ramp.

`tintColors` returns CSS `color-mix(in oklab, ...)` strings that are resolved by the browser, not
concrete color values – the result cannot be fed into functions that expect a resolved color (such
as `darken`), and it appears as a `color-mix(...)` expression, not a hex/rgb value, in computed
styles.

## OKLCH colors generator

`@mantine/colors-generator` has been updated to output OKLCH color palettes. The `generateColors`
function still returns a `MantineColorsTuple` (now containing `oklch(...)` strings) so existing
usage is unchanged:

```tsx
import { generateColors } from '@mantine/colors-generator';

const theme = createTheme({
  colors: {
    brand: generateColors('#375EAC'), // returns MantineColorsTuple of oklch strings
  },
});
```

A new `generateColorFormats` function is also available when you need the full palette in multiple
formats (oklch, hex, rgb, hsl) along with the detected base color index.
