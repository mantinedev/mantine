## Usage

The `use-form-field` hook subscribes a component to a value store carried by its `onChange`
handler. A state manager attaches a field object to the handler it hands out, and the component
that receives the handler subscribes to that field with the hook: it rerenders when the field
value changes, without the component that owns the state rerendering.

Pass the `onChange` prop to the hook. If a field is attached, `field.subscribed` is `true` and
the component must render `field.value`. If the handler is a plain function, the component keeps
using its `value` prop:

```tsx
import { useFormField } from '@mantine/hooks';

interface CustomInputProps {
  value?: string;
  onChange?: (value: string) => void;
}

function CustomInput({ value, onChange }: CustomInputProps) {
  const field = useFormField<string>(onChange);
  const currentValue = field.subscribed ? field.value : value;

  return (
    <input
      value={currentValue ?? ''}
      onChange={(event) => onChange?.(event.currentTarget.value)}
    />
  );
}
```

All Mantine inputs call this hook, as do components built with
[use-uncontrolled](/hooks/use-uncontrolled/) that pass `onChange` to it as is.

## Field protocol

A handler carries a field when it has a `FormField` object stored under
`Symbol.for('mantine-form-field')`. The object exposes the field path, a `subscribe` function
and a `getSnapshot` function used with `useSyncExternalStore`, and a `subscribeExternalWrite`
function for writes that do not come from the component. Any store can attach it:

```tsx
import { FormField } from '@mantine/hooks';

const FORM_FIELD = Symbol.for('mantine-form-field');

function attachField<Handler extends (...args: any[]) => any>(
  handler: Handler,
  field: FormField
) {
  (handler as any)[FORM_FIELD] = field;
  return handler;
}
```

## onExternalWrite

Some components keep state that the value cannot express, for example a date input with a
partially entered date reports `null` until the date is complete. When the store writes `null`
again, the value does not change and the component cannot know that it has to clear the entry.
`onExternalWrite` is called with the field value on every write that comes from the store rather
than from the component, and once with the current value when the component is bound to another
field, for example when list items are reordered or removed. The callback must update the
internal state only and must not call `onChange`:

```tsx
import { useState } from 'react';
import { useFormField } from '@mantine/hooks';

interface ExpiryInputProps {
  value?: string;
  onChange?: (value: string) => void;
}

function splitExpiry(value: string | undefined) {
  const [month = '', year = ''] = (value || '').split('/');
  return { month, year };
}

function ExpiryInput({ value, onChange }: ExpiryInputProps) {
  const [parts, setParts] = useState(() => splitExpiry(value));

  useFormField<string>(onChange, {
    subscribe: false,
    onExternalWrite: (external) => setParts(splitExpiry(external)),
  });

  const handleChange = (next: { month: string; year: string }) => {
    setParts(next);
    const complete = next.month.length === 2 && next.year.length === 2;
    onChange?.(complete ? `${next.month}/${next.year}` : '');
  };

  return (
    <div>
      <input
        placeholder="MM"
        value={parts.month}
        onChange={(event) => handleChange({ ...parts, month: event.currentTarget.value })}
      />
      <input
        placeholder="YY"
        value={parts.year}
        onChange={(event) => handleChange({ ...parts, year: event.currentTarget.value })}
      />
    </div>
  );
}
```

Set `subscribe: false` when the component renders the `value` prop instead of the subscribed
value. The store is then responsible for rerendering the component that passes `value`.

## Definition

```tsx
interface UseFormFieldOptions<Value = any> {
  /** If set, the component is subscribed to the field value and must render the returned `value` instead of the `value` prop, `true` by default */
  subscribe?: boolean;

  /** Called with the field value when the store writes it and when the component is bound to another field. Not called for changes reported by the component itself. Must not call `onChange`. */
  onExternalWrite?: (value: Value) => void;
}

interface UseFormFieldReturnValue<Value = any> {
  /** `true` if the handler carries a field */
  bound: boolean;

  /** `true` if the component is subscribed to the field value and must render `value` */
  subscribed: boolean;

  /** Path of the field in the store, `null` if the component is not bound */
  path: string | null;

  /** Current field value, `undefined` if the component is not subscribed */
  value: Value | undefined;
}

function useFormField<Value = any>(
  onChange: unknown,
  options?: UseFormFieldOptions<Value>
): UseFormFieldReturnValue<Value>;
```

## Exported types

The `UseFormFieldOptions`, `UseFormFieldReturnValue` and `FormField` types are exported from `@mantine/hooks`:

```tsx
import type { UseFormFieldOptions, UseFormFieldReturnValue, FormField } from '@mantine/hooks';
```

## Usage with @mantine/form

[use-form](/form/use-form/) attaches a field to every `onChange` handler returned by
`form.getInputProps` and `field.getInputProps`, handlers returned by [use-field](/form/use-field/)
for `type: 'radio'` are the exception. A custom input that calls `use-form-field` rerenders on its
own when its field changes, and the component that called `useForm` does not. The form writes the
field with `form.setFieldValue`, `form.setValues`, `form.reset`, `form.resetField`,
`form.initialize` and list handlers, these writes reach `onExternalWrite`. When a bound input
is not subscribed (`subscribe: false`), the form rerenders the component that called `useForm`
instead, so the input receives a new `value` prop:

```tsx
import { useForm } from '@mantine/form';
import { CustomInput } from './CustomInput';

function Demo() {
  const form = useForm({ initialValues: { name: '' } });

  // CustomInput calls useFormField(onChange) and rerenders alone
  return <CustomInput {...form.getInputProps('name')} />;
}
```

In uncontrolled mode, bind each field path to a single input. A component that is not subscribed
is not updated while the user types in a subscribed input of the same path. Call `use-form-field`
in every component bound to that path or switch the form to controlled mode, see
[one input per field path](/form/uncontrolled#one-input-per-field-path).

See the [custom input](/form/examples?e=CustomInputSubscription) and
[rich text](/form/examples?e=RichTextForm) form examples, and the
[get-input-props](/form/get-input-props/) guide.
