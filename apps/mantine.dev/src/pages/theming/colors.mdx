# Colors

Mantine's default theme includes 14 color palettes, each with 10 shades. In v10 all default
palettes were re-derived in the [OKLCH](https://oklch.com/) color space on a shared
perceptual-lightness ramp: every shade index has the same perceived brightness across all hues,
so filled buttons and other colored controls look visually consistent regardless of color.

Colors are exposed on the [theme object](/theming/theme-object) as an array of strings.
You can access a color shade by color name and index (0-9); colors with a larger index are darker:

```tsx
import { useMantineTheme } from '@mantine/core';

function Demo() {
  const theme = useMantineTheme();

  return (
    <div
      style={{
        backgroundColor: theme.colors.blue[1],
        color: theme.colors.blue[9],
      }}
    >
      This is a blue theme
    </div>
  );
}
```

Colors are also exposed as [CSS variables](/styles/css-variables):

```scss
.demo {
  color: var(--mantine-color-red-5);
  background: var(--mantine-color-grape-9);
  border: 1px solid var(--mantine-color-blue-1);
}
```

> **OKLCH CSS variables**
>
> In v10, `--mantine-color-*` variables emit `oklch(L C H)` strings instead of hex/RGB.
> Code that reads these values and parses them as hex or RGB must be updated.
> See the [9.x → 10.x migration guide](/guides/9x-to-10x) for details and the one-line v9 opt-out.

## Adding extra colors

You can add any number of extra colors to the `theme.colors` object.
This will allow you to use them in all components that support the `color` prop, for example
[Button](/core/button), [Badge](/core/badge), and [Switch](/core/switch).

<Demo data={ThemingDemos.colorsOverride} />

> **10 shades per color**
>
> A colors override must include **at least 10 shades per color**. Otherwise, you will get a TypeScript error
> and some variants will not have proper colors. If you only have one color value, you can either
> pick the remaining colors manually or use the [colors generator tool](https://themes.mantine.dev/colors-generator/).
>
> You can add more than 10 shades per color: these values will not be used by Mantine components with the default colors resolver,
> but you can still reference them by index, for example, `color="blue.11"`.

## Virtual colors

A virtual color is a special color whose values should be different for light and dark color schemes.
To define a virtual color, use the `virtualColor` function which accepts an object with the following
properties as a single argument:

- `name` – color name, must be the same as the key in `theme.colors` object
- `light` – a key of `theme.colors` object for light color scheme
- `dark` – a key of `theme.colors` object for dark color scheme

To see the demo in action, switch between light and dark color schemes (`Ctrl + J`):

<Demo data={ThemingDemos.virtualColors} />

Virtual colors support [autoContrast](/theming/theme-object/#autocontrast): the text color of `filled`
components is calculated separately for each color scheme based on the resolved background color.
`autoContrast` is enabled by default – switch between light and dark color schemes (`Ctrl + J`) to
see the text color adjust to the underlying virtual color:

<Demo data={ThemingDemos.virtualColorsAutoContrast} />

## colorsTuple

Use the `colorsTuple` function to:

- Use a single color as the same color for all shades
- Transform dynamic string arrays to Mantine color tuple (the array should still have 10 values)

```tsx
import { colorsTuple, createTheme } from '@mantine/core';

const theme = createTheme({
  colors: {
    custom: colorsTuple('#FFC0CB'),
    dynamic: colorsTuple(
      Array.from({ length: 10 }, (_, index) => '#FFC0CB')
    ),
  },
});
```

## Supported color formats

You can use the following color formats in `theme.colors`:

- HEX: `#fff`, `#ffffff`
- RGB: `rgb(255, 255, 255)`, `rgba(255, 255, 255, 0.5)`
- HSL: `hsl(0, 0%, 100%)`, `hsla(0, 0%, 100%, 0.5)`
- OKLCH: `oklch(96.27% 0.0217 238.66)`, `oklch(96.27% 0.0217 238.66 / 0.5)`

## primaryColor

`theme.primaryColor` is a key of `theme.colors`, it is used:

- As a default value for most of the components that support `color` prop
- To set default focus ring outline color

<Demo data={ThemingDemos.primaryColor} />

> **CSS color values at `theme.primaryColor`**
>
> The value of `theme.primaryColor` must be a key of the `theme.colors` object. For example, `blue`, `orange`, or `green`.
> You cannot assign CSS color values; for example, the following code will throw an error during theme merging:
>
> ```tsx
> import { MantineProvider } from '@mantine/core';
>
> function Demo() {
>   return (
>     <MantineProvider
>       theme={{
>         primaryColor: '#CEFEDC', // This will throw an error
>       }}
>     >
>       {/* Your app here */}
>     </MantineProvider>
>   );
> }
> ```

## primaryShade

`theme.primaryShade` is a number from 0 to 9. It determines which shade will be used for components that have a `color` prop.

<Demo data={ThemingDemos.primaryShadeConfigurator} />

You can also customize primary shade for dark and light color schemes separately:

```tsx
import { MantineProvider } from '@mantine/core';

function Demo() {
  return (
    <MantineProvider theme={{ primaryShade: { light: 6, dark: 8 } }}>
      {/* Your app here */}
    </MantineProvider>
  );
}
```

## autoContrast

`theme.autoContrast` controls whether filled controls automatically switch their text color between
black and white based on the luminance of their background. It defaults to `true` in v10.

When `autoContrast` is enabled, any component that accepts a `color` prop and renders in the
`filled` variant will pick the highest-contrast text color (black or white) automatically. This is
especially useful when using light shades as the filled color:

```tsx
import { Button, MantineProvider } from '@mantine/core';

// autoContrast is on by default – text color is chosen automatically
function Demo() {
  return <Button color="yellow.3">Label</Button>;
}
```

To disable `autoContrast` globally, set it to `false` in the theme:

```tsx
import { createTheme, MantineProvider } from '@mantine/core';

const theme = createTheme({
  autoContrast: false,
});

function Demo() {
  return <MantineProvider theme={theme}>{/* Your app */}</MantineProvider>;
}
```

`theme.luminanceThreshold` controls the luminance cutoff (default `0.2`). Backgrounds with
relative luminance above the threshold get black text; those below get white text.

## Semantic color variables

In addition to the raw shade variables (`--mantine-color-gray-3`, etc.), Mantine v10 exposes
semantic role tokens that components use internally. You can override these to theme borders,
surfaces, and text uniformly:

```css
[data-mantine-color-scheme='light'] {
  --mantine-color-border: #d0d5dd;
  --mantine-color-text-muted: #6b7280;
}

[data-mantine-color-scheme='dark'] {
  --mantine-color-border: #374151;
  --mantine-color-text-muted: #9ca3af;
}
```

Role variables are defined as `var()` references to the underlying shade variables, so overriding
`--mantine-color-gray-3` still cascades into `--mantine-color-border`. `--mantine-color-body` is
aliased to `--mantine-color-surface-page`, so overriding the latter also updates the page background.

`--mantine-color-focus-ring` is the color of every focus ring: the `.mantine-focus-auto` /
`.mantine-focus-always` outline and the focused `Input` border. It follows `theme.primaryColor`, but
unlike `--mantine-primary-color-filled` it uses shade 5 in dark mode instead of `primaryShade.dark`,
so the ring stays legible against dark backgrounds. Override it to restyle focus rings everywhere
without touching filled buttons.

scheme-agnostic by role – index `N` means the same thing in both color schemes – while the

Mantine components consume this ladder directly for neutral surfaces that have no dedicated role
token – striped table rows, filled fieldsets and accordions, chart empty cells, checkerboard
overlays, drag handles and similar – so overriding `--mantine-color-neutral-N` re-themes them
together with the role tokens. A few component styles intentionally keep scheme-specific values
and are not affected by ladder overrides: code blocks rendered with a forced `codeColorScheme`
(`CodeHighlight`), the inverted `Tooltip` and `Slider` label bubbles, and the accent-tinted
drag-and-drop targets in `@mantine/schedule`.

## tintColors

Use the `tintColors` function to mix a color into every shade of a `MantineColorsTuple`, useful for
building a custom-tinted dark ramp without hand-editing 10 shades. It targets the **dark** ramp –
tinting light neutrals forces surfaces darker and breaks the flat light look, so keep tinting to
dark:

```tsx
import { tintColors, darkColors, createTheme } from '@mantine/core';

const theme = createTheme({
  colors: {
    dark: tintColors(darkColors, '#5c7cfa', 0.15),
  },
});
```

`strength` (default `0.1`) controls how much of the tint is mixed in. Middle shades of the tuple
receive proportionally more tint than the shades near either end of the ramp.

`tintColors` returns CSS `color-mix(in oklab, ...)` strings that are resolved by the browser, not
concrete color values – the result cannot be fed into functions that expect a resolved color (such
as `darken`), and it appears as a `color-mix(...)` expression, not a hex/rgb value, in computed
styles.

## Surface component

[Surface](/core/surface) is the depth-aware background primitive introduced in v10. It replaces
`Paper` (deprecated in v10, removed in v11) and supports automatic elevation stepping in dark mode –
each nested `Surface` renders one level above its parent by default:

```tsx
import { Surface } from '@mantine/core';

function Demo() {
  return (
    <Surface shadow="sm" radius="md" p="md">
      <Surface p="md">
        Inner surface – one level deeper in dark mode
      </Surface>
    </Surface>
  );
}
```

Depth can also be set explicitly with the `level` prop, either as an absolute `0`–`2` value or as a
relative string like `level="+1"`/`level="-1"` that steps from the parent surface's level. Either
form overrides `autoDepth` and clamps to the `0`–`2` range. See the
[Surface documentation](/core/surface) for all details.

Surface backgrounds can be overridden per color scheme with the `surfaces` theme key, without
touching CSS variables directly:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  surfaces: {
    dark: {
      panel: '#101113',
    },
  },
});
```

Each scheme (`light`/`dark`) accepts `page`, `panel`, `panel2`, `sunken`, `muted` and `input` keys,
matching the six surface tokens documented above.

`--mantine-color-surface-input` is the background of inputs, checkboxes, radios, `Dropzone` and
`RichTextEditor`. It is white in light mode and `dark-7` in dark mode, one shade above the page, so
fields stand out from the page background.

`--mantine-color-surface-muted` is the background of code and inset content – `Code`, `Kbd`,
`CodeHighlight`, `JsonViewer`, `Typography` `pre`/`code`/`kbd`, striped table rows and filled
`Fieldset` and `Accordion`. It is one step off the page in both color schemes (`gray-0` / `dark-7`).
`--mantine-color-surface-sunken` stays on the well value (`gray-1` / `dark-9`) used by the
`SegmentedControl` root, the `Tabs` `contained` list, and `ScrollArea` scrollbars, where a raised
indicator sits inside the well.

## Difference between color and c props

The `color` prop is used to control multiple CSS properties of the component. These properties can vary across different components,
but usually the `color` prop controls `background`, `color`, and `border-color` CSS properties. For example,
when you set `color="#C3FF36"` on the [Button](/core/button) component (with `variant="filled"`), it will set the following CSS properties:

- `background-color` to `#C3FF36`
- `background-color` when the button is hovered to `#B0E631` (`#C3FF36` darkened by 10%)
- `color` to `var(--mantine-color-white)`
- `border-color` to `transparent`

`c` is a [style prop](/styles/style-props) – it is responsible for setting a single CSS property `color` (color of the text).
You can combine both props to achieve better contrast between text and background. In the following example:

- The `color` prop sets `background: #C3FF36` and `color: var(--mantine-color-white)`
- The `c` prop overrides color styles to `color: var(--mantine-color-black)`

## Colors variant resolver

`theme.variantColorResolver` is a function that is used to determine which colors will be used
in different variants in the following components: [Alert](/core/alert), [Avatar](/core/avatar), [Button](/core/button), [Badge](/core/badge), and [ActionIcon](/core/action-icon).

It accepts an object argument with the following properties:

```tsx
interface VariantColorsResolverInput {
  /** `color` prop passed to component */
  color: MantineColor | undefined;

  /** `variant` prop passed to component */
  variant: string;

  /** `gradient` prop passed to component, used only for gradient variant by default */
  gradient?: MantineGradient;

  /** Theme object */
  theme: MantineTheme;
}
```

`theme.variantColorResolver` must return an object with the following properties:

```tsx
interface VariantColorResolverResult {
  background: string;
  hover: string;
  color: string;
  border: string;
}
```

or to add support for new variants:

## Colors generation

Use the [colors generator](https://themes.mantine.dev/colors-generator/) to generate 10 shades from a single color.
To generate colors at runtime, install the `@mantine/colors-generator` package:

<InstallScript packages="@mantine/colors-generator" />

`generateColors` accepts any CSS color and returns a `MantineColorsTuple` of 10 OKLCH shades.
The input color is kept as is at the shade that matches its lightness, the other shades are built around it:

```tsx
import { generateColors } from '@mantine/colors-generator';
import { MantineProvider } from '@mantine/core';

function Demo() {
  return (
    <MantineProvider
      theme={{
        colors: {
          brand: generateColors('#375EAC'),
        },
      }}
    >
      {/* Your app here */}
    </MantineProvider>
  );
}
```

The second argument adjusts the generated shades. All options are optional:

```tsx
import { generateColors } from '@mantine/colors-generator';

const yellow = generateColors('#fcc419', {
  // Shade that is set to the input color, 0-9, 'auto' by default
  baseShade: 6,
  // Lightness of shades 0 and 9, 0-1
  lightest: 0.97,
  darkest: 0.4,
  // Saturation of shades 0 and 9 relative to the input color, 0-1
  lightestChroma: 0.1,
  darkestChroma: 0.8,
  // Hue rotation in degrees from shade 0 to shade 9
  hueShift: -25,
});
```

`generateColorFormats` returns the palette in oklch, hex, rgb and hsl formats together with the index of the base shade:

```tsx
import { generateColorFormats } from '@mantine/colors-generator';

const result = generateColorFormats('#375EAC', { baseShade: 7 });
// result.colors       – MantineColorsTuple (oklch strings)
// result.formats.hex  – string[]
// result.formats.rgb  – string[]
// result.baseColorIndex – 7
```

## Add custom colors types

TypeScript will only autocomplete Mantine's default colors when accessing the theme. To add your custom colors to the MantineColor type, you can use TypeScript module declaration.

```ts
import {
  DefaultMantineColor,
  MantineColorsTuple,
} from '@mantine/core';

type ExtendedCustomColors =
  | 'primaryColorName'
  | 'secondaryColorName'
  | DefaultMantineColor;

declare module '@mantine/core' {
  export interface MantineThemeColorsOverride {
    colors: Record<ExtendedCustomColors, MantineColorsTuple>;
  }
}
```
