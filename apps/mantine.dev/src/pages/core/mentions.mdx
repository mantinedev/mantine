## Usage

`Mentions` is a textarea that opens a suggestions dropdown when the user types a trigger character,
for example `@` or `#`. Picking a suggestion inserts a mention into the value. Mentions are atomic:
deleting any part of a mention removes the whole mention.

<Demo data={MentionsDemos.usage} />

## Value and markup

`Mentions` value is a markup string: each mention is stored as `@[__display__](__id__)`,
while the user sees only the display text. For example, the value:

```tsx
'Hey @[Walter White](walter), are you there?';
```

is displayed as `Hey Walter White, are you there?`. When `name` is set, the markup value
is submitted with native forms.

By default, the trigger character is not displayed. Set `withTrigger` on `Mentions.Mention`
to display the same value as `Hey @Walter White, are you there?`:

<Demo data={MentionsDemos.showTrigger} />

## onChange payload

Unlike other Mantine inputs, `Mentions` `onChange` is called with an object instead of a string:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions
      onChange={(payload) => {
        payload.value; // Markup value: "Hey @[Walter White](walter)"
        payload.plainTextValue; // What the user sees: "Hey Walter White"
        payload.idValue; // Display replaced by id: "Hey walter"
        payload.mentions; // Array of mentions present in the value
        payload.mentionId; // Id of the mention that triggered the change, if any
        payload.previousValue; // Previous markup value
        payload.reason; // { type, nativeEvent } – what caused the change
      }}
    >
      <Mentions.Mention trigger="@" data={[{ id: 'walter', display: 'Walter White' }]} />
    </Mentions>
  );
}
```

`payload.reason.type` is one of:

- `'input'` – regular typing or deletion that does not remove a mention
- `'mention-add'` – a suggestion was inserted (`payload.mentionId` is set)
- `'mention-remove'` – an edit removed one or more mentions
- `'paste'` – text was pasted
- `'cut'` – a selection was cut
- `'insert-text'` – text was dragged and dropped into the field
- `'undo'` and `'redo'` – the change came from the undo history

## onAdd

`onAdd` on `Mentions.Mention` is called when a suggestion is inserted. `startPos` and `endPos`
are positions in the text the user sees, not in the markup value:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions>
      <Mentions.Mention
        trigger="@"
        data={[{ id: 'walter', display: 'Walter White' }]}
        onAdd={({ id, display, startPos, endPos }) => {
          console.log(`Mentioned ${display} (${id}) at ${startPos}–${endPos}`);
        }}
      />
    </Mentions>
  );
}
```

## Copy and paste

Mentions are kept when text is copied or cut and then pasted into a `Mentions` field
that has the same triggers. Other applications receive plain text. A mention that is
selected only partially is copied as plain text.

## RegExp triggers

`trigger` also accepts a `RegExp` that matches the trigger character. Mentions of a `RegExp`
trigger are stored as `@[__display__](__id__)`, use `markup` prop to change that.
For example, the source below opens the dropdown on both `@` and `+`:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions>
      <Mentions.Mention trigger={/[@+]/} data={users} />
    </Mentions>
  );
}
```

To control how the query is matched, use a `RegExp` with two capture groups. It must be
anchored to the end of the text with `$`, group 1 must capture the trigger with the query
and group 2 the query.

## Data sources

`data` prop of `Mentions.Mention` accepts an array of `{ id, display }` items or a function
that returns matches. Array data is filtered by the query: an item matches when its `display`
or `id` contains the query, case-insensitively.

- Set `ignoreAccents` to ignore accents when filtering array data, for example to match `José` with `jose`
- Set `allowSpaceInQuery` to allow spaces in the query. By default, the query ends at the first whitespace.

## Custom filter

Use `filter` prop of `Mentions` to change how array data is filtered. Set `filter={false}`
to display array data as is, for example when it is already filtered on the server.

```tsx
import { Mentions, MentionsFilter } from '@mantine/core';

const startsWithFilter: MentionsFilter = ({ query, items }) =>
  items.filter((item) => (item.display ?? item.id).toLowerCase().startsWith(query.toLowerCase()));

function Demo() {
  return (
    <Mentions filter={startsWithFilter}>
      <Mentions.Mention trigger="@" data={[{ id: 'walter', display: 'Walter White' }]} />
    </Mentions>
  );
}
```

## maxSuggestions

Set `maxSuggestions` on `Mentions.Mention` to limit the number of displayed suggestions:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (

      <Mentions.Mention trigger="@" data={users} maxSuggestions={5} />

```

## Loading, empty and error states

Use `loadingMessage`, `errorMessage` and `nothingFoundMessage` props of `Mentions` to change
messages displayed in the dropdown. To change empty and error states of a single source,
use `renderEmpty` and `renderError` on `Mentions.Mention`:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions
      loadingMessage="Searching users…"
      errorMessage="Could not load users"
      nothingFoundMessage="No users found"
    >
      <Mentions.Mention
        trigger="@"
        data={searchUsers}
        renderEmpty={(query) => `No users match "${query}"`}
        renderError={(query) => `Search for "${query}" failed`}
      />
    </Mentions>
  );
}
```

## Custom markup

Use `markup` prop of `Mentions.Mention` to change how mentions are stored, for example
`{{__id__}}`. If the format cannot be described with a template, pass a serializer object
with `insert` and `findAll` methods.

With the default markup, `id` must not contain `)` and `display` must not contain `](`.
If your data can contain these characters, use a serializer object.

## displayTransform

`displayTransform` on `Mentions.Mention` changes the displayed text of mentions without
changing the value:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions defaultValue="Assigned to @[Walter White](walter)">
      <Mentions.Mention
        trigger="@"
        data={users}
        displayTransform={(id, display) => display.split(' ')[0]}
      />
    </Mentions>
  );
}
```

The value above is displayed as `Assigned to Walter`, while the markup still stores the full
`Walter White` display.

## Mention styles

Set `className` and `style` on `Mentions.Mention` to style mentions of a single source:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions>
      <Mentions.Mention trigger="@" data={users} />
      <Mentions.Mention
        trigger="#"
        data={tags}
        style={{ backgroundColor: 'var(--mantine-color-teal-light)' }}
      />
    </Mentions>
  );
}
```

To style mentions of all sources, use the `highlight` Styles API selector or the
`--mentions-highlight-color` and `--mentions-highlight-bg` CSS variables.

## Anchor mode

By default, the dropdown is displayed below the caret. Set `anchorMode="left"` to align it
with the left edge of the input. Use `suggestionsPlacement` to display it above the input (`above`)
or on the side with more space (`auto`).

## Inline suggestions

Set `suggestionsDisplay="inline"` to display the first match as ghost text at the caret
instead of the dropdown. The ghost text is displayed only when the match starts with the query.
Press `Tab` or `Enter` to accept it:

<Demo data={MentionsDemos.inline} />

## Caret-aware styling

Mentions have `data-mention-selection` attribute that you can use to style them based on
the caret position and selection:

- `inside` – the caret is inside the mention
- `boundary` – the caret is at the edge of the mention
- `partial` – a part of the mention is selected
- `full` – the whole mention is selected

<Demo data={MentionsDemos.caretStyling} />

`onSelectionChange` is called with the current selection and the mentions it overlaps.

## Parsing mentions

Use `getMentions` function to get mentions from a markup value, for example on submit:

```tsx
import { getMentions } from '@mantine/core';

const mentions = getMentions('Hey @[Walter White](walter)', [{ trigger: '@' }]);
// [{ id: 'walter', display: 'Walter White', index: 4, plainTextIndex: 4, trigger: '@' }]
```

`@mantine/core` also exports `createMarkupSerializer` to build a serializer from a template
string and `makeTriggerRegex` to build a trigger `RegExp`.

## Undo and redo

`Mentions` keeps its own undo history instead of the native one: undo and redo shortcuts
restore removed mentions. Changes of a controlled `value` made outside of the component,
for example a form reset, can be undone as well.

## Single line

Set `singleLine` to render an `input` instead of a `textarea`:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions singleLine label="Assignee" placeholder="Type @ to mention someone">
      <Mentions.Mention trigger="@" data={users} />
    </Mentions>
  );
}
```

## Disabled and static

Set `disabled` to disable the input. Set `mode="static"` to display a value with mentions
that cannot be edited:

```tsx
import { Mentions } from '@mantine/core';

function Demo() {
  return (
    <Mentions mode="static" defaultValue="Ping @[Walter White](walter) about it">
      <Mentions.Mention trigger="@" />
    </Mentions>
  );
}
```

## Accessibility

Set `label` or `aria-label` prop to label the input. The suggestions list is labelled
`Suggestions`, use `a11ySuggestionsListLabel` prop to change or translate the label.

Keyboard interactions while the suggestions dropdown is open:

- <kbd>ArrowDown</kbd> / <kbd>ArrowUp</kbd> – highlight the next/previous suggestion
- <kbd>Enter</kbd> / <kbd>Tab</kbd> – insert the highlighted suggestion
- <kbd>Escape</kbd> – close the dropdown. Inside `Modal` or `Drawer`, the first <kbd>Escape</kbd>
  closes the dropdown only

Keyboard interactions with `suggestionsDisplay="inline"` while the ghost text is visible:

- <kbd>Tab</kbd> / <kbd>Enter</kbd> – accept the suggestion
- <kbd>→</kbd> – accept the suggestion when the caret is at the end of the text
- <kbd>Escape</kbd> – dismiss the suggestion
