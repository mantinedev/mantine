## Usage

`Timer` is a controllable countdown and stopwatch readout. Unlike a fire-and-forget
display, it has running/paused state, counts up or down, and can be started, paused, resumed,
reset and restarted. `Timer` does not render playback buttons – build them with
[Timer.Control](#custom-layout) or drive the timer with an external [useTimer](#controlling-the-timer)
controller. Set `autoStart` to start the timer on mount:

<Demo data={TimerDemos.usage} />

## Countdown and stopwatch

By default `Timer` works as a stopwatch: it counts up from `startMs` (`0` by default). Set the
`countdown` prop to count down instead. In countdown mode `startMs` is the initial duration and
the timer counts down to `targetMs` (`0` by default):

```tsx
import { Timer } from '@mantine/core';

function Demo() {
  return (
    <>
      {/* Stopwatch: counts up from 0 */}
      <Timer autoStart />

      {/* Countdown: counts down from 90 seconds to 0 */}
      <Timer countdown startMs={90 * 1000} autoStart />
    </>
  );
}
```

In stopwatch mode you can set `targetMs` to count up to a boundary – the timer stops and calls
`onComplete` once the target is reached. In countdown mode the timer completes when it reaches
`targetMs`.

If `startMs` is already at or past the boundary (a countdown with `startMs` below `targetMs`, or a stopwatch with `targetMs` below `startMs`), the timer completes immediately when it is started and calls `onComplete`. Changing `startMs` or `countdown` stops the timer and resets it to the new `startMs`.

## Format

The default readout is rendered with the `format` prop, `'HH:mm:ss'` by default. The following
tokens are supported:

<DataTable
  head={['Token', 'Description', 'Example']}
  data={[
    ['DD / D', 'Days, padded to 2 digits / not padded', '02 / 2'],
    ['HH / H', 'Hours (0–23), padded / not padded', '09 / 9'],
    ['mm / m', 'Minutes (0–59), padded / not padded', '05 / 5'],
    ['ss / s', 'Seconds (0–59), padded / not padded', '07 / 7'],
    ['SSS', 'Milliseconds, padded to 3 digits', '040'],
    ['SS', 'Centiseconds, padded to 2 digits', '04'],
    ['S', 'Milliseconds, not padded', '40'],
  ]}
/>

Literal text in `format` is not escaped: the letters `D`, `H`, `m`, `s` and `S` are always replaced with time values, even inside words.

Each token renders its own time segment. Days accumulate all higher units, but other tokens are
capped to their natural range (hours 0–23, minutes and seconds 0–59). Include a larger token
(for example `DD` or `HH`) for durations that exceed the largest unit in the format:

<Demo data={TimerDemos.formats} />

To display milliseconds or centiseconds, lower the `interval` prop so the readout updates more
frequently than once per second:

## Custom layout

For custom layouts, pass `Timer.Segment`, `Timer.Separator` and `Timer.Control` as children
instead of relying on the default readout. `Timer.Segment` displays a single time segment,
`Timer.Separator` renders a separator between segments, and `Timer.Control` is a button that calls
a controller action when clicked:

<Demo data={TimerDemos.segments} />

`Timer.Segment` `type` prop accepts `days`, `hours`, `minutes`, `seconds` and `milliseconds`.
`Timer.Control` `action` prop accepts `start`, `pause`, `resume`, `reset` and `restart`. `start`
continues from the current value, or restarts the timer from `startMs` if it has already completed.

## useTimer hook

`Timer` component supports the [controller pattern](/guides/controllers). Use the `useTimer` hook
to manage `Timer` state, to build a fully custom timer UI or to share one timer controller between
several components. `useTimer` accepts the timer-specific options (`startMs`, `targetMs`,
`countdown`, `interval`, `autoStart`, `onTick` and `onComplete`) – the same as the corresponding
[Timer props](/core/timer?t=props), but not the DOM and style props – and returns the timer state
and actions:

```tsx
import { useTimer } from '@mantine/core';

function Demo() {
  const controller = useTimer({ countdown: true, startMs: 60 * 1000 });

  controller.getValue(); // -> { totalMs, days, hours, minutes, seconds, milliseconds }
  controller.isRunning(); // -> boolean, true while the timer is counting
  controller.isPaused(); // -> boolean, true when the timer is started and then paused
  controller.getProgress(); // -> number from 0 to 1 when the boundary is set

  controller.start(); // starts from the current value, or from startMs after the timer has completed
  controller.pause();
  controller.resume();
  controller.reset(); // stops and resets the value to startMs
  controller.restart(); // resets and starts again

  return null;
}
```

## Controlling the timer

To control the timer from outside the component, create a controller with `useTimer` and pass it
to `Timer` with the `controller` prop. When a controller is provided, the option props on `Timer`
are ignored – the controller owns the state. See the [Controllers](/guides/controllers) guide for
how the pattern works across all components:

## Progress

When `targetMs` is set (or in countdown mode, where it defaults to `0`), the controller's
`getProgress()` returns a value from `0` to `1`. It is convenient for binding the timer to a
[Progress](/core/progress) bar or a [RingProgress](/core/ring-progress):

## Timer.parse

`Timer.parse` (also available as `useTimer.parse`) converts a duration object, `Date` or ISO date
string to milliseconds. It is useful for the "count down to a date" scenario or for building
`startMs`/`targetMs` values from time units:

```tsx
import { Timer } from '@mantine/core';

Timer.parse(90 * 1000); // -> 90000
Timer.parse({ minutes: 25 }); // -> 1500000
Timer.parse({ hours: 1, minutes: 30 }); // -> 5400000
Timer.parse('2030-01-01T00:00:00'); // -> milliseconds from now until the date
```

When `Timer.parse` receives a `Date` or a date string, the result depends on the current time, so every call returns a different value. Compute it once (for example, with a `useState` initializer) – passing `Timer.parse(date)` directly to `startMs` gives the timer a new `startMs` on every render, and a changed `startMs` stops and resets the timer:

<Demo data={TimerDemos.deadline} />

A date in the past produces a negative value, which `Timer` clamps to `0`, so a countdown with `autoStart` completes on mount. A string that cannot be parsed as a date produces `0`.

## Timer vs use-countdown

[use-countdown](/hooks/use-countdown) is a display-only countdown hook: it counts down to a target
date or from a duration and fires `onComplete`. `Timer` and `useTimer` are the interactive
superset – they count up or down, expose pause/resume/restart controls and compound layout parts.
Reach for `use-countdown` when you only need a countdown readout, and for `Timer`/`useTimer` when
you need full playback control.

## Accessibility

The `Timer` root element has `role="timer"` and `aria-live="off"`, so screen readers do not announce every tick. To announce the value as it changes, set `aria-live="polite"` on `Timer` – it is recommended only for second (or slower) `interval` values, and keep `Timer.Control` elements outside of the announced region if you do not want their labels to be read on every update. `Timer.Control` controls are real `button` elements. When a control renders only an icon, set an `aria-label`:

```tsx
import { Timer } from '@mantine/core';

function Demo() {
  return (
    <Timer countdown startMs={60 * 1000}>
      <Timer.Segment type="minutes" />
      <Timer.Separator />
      <Timer.Segment type="seconds" />
      <Timer.Control action="start" aria-label="Start timer">
        ▶
      </Timer.Control>
    </Timer>
  );
}
```
