## Usage

`Menubar` is a desktop-application style menu bar: a horizontal row of triggers
(File, Edit, View, …), each of them opens a dropdown. `Menubar` is built on top of
[Menu](/core/menu), dropdown content is composed from `Menu.Item`, `Menu.Divider` and other
`Menu` components.

<Demo data={MenubarDemos.usage} />

## How it differs from Menu

[Menu](/core/menu) is one target that toggles one dropdown. `Menubar` coordinates multiple menus:

- Only one menu is open at a time. Moving to another target while a menu is open switches the open menu.
- The whole bar is a single tab stop, arrow keys move focus between targets.

If you need a single dropdown attached to one button, use [Menu](/core/menu) instead.

## Composition

- `Menubar` – root element
- `Menubar.Menu` – wraps a single menu, accepts the same props as `Menu`
- `Menubar.Target` – top-level trigger button
- `Menubar.Dropdown` – dropdown container, accepts the same children as `Menu.Dropdown`

```tsx
import { Menu, Menubar } from '@mantine/core';

function Demo() {
  return (
    <Menubar>
      <Menubar.Menu>
        <Menubar.Target>File</Menubar.Target>
        <Menubar.Dropdown>
          <Menu.Item>New file</Menu.Item>
          <Menu.Item>Open…</Menu.Item>
        </Menubar.Dropdown>
      </Menubar.Menu>

      <Menubar.Menu>
        <Menubar.Target>Edit</Menubar.Target>
        <Menubar.Dropdown>
          <Menu.Item>Undo</Menu.Item>
          <Menu.Item>Redo</Menu.Item>
        </Menubar.Dropdown>
      </Menubar.Menu>
    </Menubar>
  );
}
```

## Trigger and loop

By default, a menu opens when its target is clicked. Once a menu is open, hovering another
target switches to it. Set `trigger="hover"` to open menus on hover, the menu closes when
the pointer leaves the bar:

<Demo data={MenubarDemos.hover} />

Set `loop={false}` to stop arrow key navigation from wrapping around from the last menu
to the first and vice versa.

## Submenus

Use `Menu.Sub` inside `Menubar.Dropdown` to create nested submenus, see the
[Menu submenus documentation](/core/menu/#submenus). The [usage demo](#usage) includes
a submenu in the File menu.

## Checkbox and radio items

Use `Menu.CheckboxItem` for toggles and `Menu.RadioGroup` with `Menu.RadioItem` for
single-choice options. By default, clicking these items does not close the menu.

<Demo data={MenubarDemos.selectable} />

## Controlled

Use `openIndex` and `onOpenChange` props to control which menu is open. `openIndex` is the
index of the opened `Menubar.Menu` or `null` when all menus are closed:

<Demo data={MenubarDemos.controlled} />

Use `defaultOpenIndex` to open a menu initially without controlling the state.

## Controlling with useMenubar

`Menubar` component supports the [controller pattern](/guides/controllers). Use the `useMenubar` hook to manage `Menubar` state:

<Demo data={MenubarDemos.controller} />

`useMenubar` accepts the state options that `Menubar` accepts as props, and returns the current
state, actions and queries:

```tsx
import { Menubar, useMenubar } from '@mantine/core';

function Demo() {
  const controller = useMenubar({
    defaultOpenIndex: 0, // -> uncontrolled initial value
    loop: false, // -> same as the loop prop of Menubar
    // openIndex, onOpenChange -> controlled state, same as on Menubar
  });

  // Actions
  controller.openMenu(1); // -> opens the menu and moves the tab stop to it
  controller.openMenu(1, 'hover'); // -> same, recorded as opened by hover
  controller.closeMenu();
  controller.toggleMenu(1);
  controller.setOpenIndex(1); // -> sets the index directly, null closes all menus
  controller.setActiveIndex(1); // -> moves the tab stop without moving DOM focus

  // Focus actions
  controller.focusMenu(1); // -> moves the tab stop to the menu and focuses its target
  controller.focusNextMenu(); // -> next enabled menu, respects loop
  controller.focusPreviousMenu();
  controller.focusFirstMenu();
  controller.focusLastMenu();
  controller.focusMenuItem(1, 'first'); // -> focuses the first item of the opened menu dropdown

  // Queries
  controller.getOpenIndex(); // -> index of the opened menu, null when all menus are closed
  controller.getActiveIndex(); // -> index of the menu that holds the menubar tab stop
  controller.isMenuOpen(1); // -> boolean
  controller.getMenuCount(); // -> number of Menubar.Menu components rendered by Menubar
  controller.getEnabledIndexes(); // -> indexes of the menus that are not disabled
  controller.getOpenSource(); // -> 'click' | 'hover' | null

  return <Menubar controller={controller}>{/* menus */}</Menubar>;
}
```

The controller owns the state, so when the `controller` prop is set, the `openIndex`,
`defaultOpenIndex`, `onOpenChange` and `loop` props of `Menubar` are ignored – pass them to
`useMenubar` instead. `trigger` and `position` are not owned by the controller and keep working as
props.

Every query and focus action reads the targets rendered by the associated `Menubar`, which reports
its root element to the controller when it mounts. They are no-op (`getMenuCount()` returns `0`,
`getEnabledIndexes()` returns an empty array) while no `Menubar` is mounted with the controller, and
they are functions rather than fields because the rendered menus are not reactive – reading them
does not re-render the component that owns the controller. One controller drives one `Menubar`:
the root element is replaced rather than accumulated, so two `Menubar` components sharing a
controller report only the menus of the one that mounted last.

`focusMenuItem` focuses an item of a dropdown that is already opened. Call it after `openMenu` – it
waits for the dropdown to render before moving focus, so the two compose into "open this menu and
step into it", which is what a global keyboard shortcut needs.

The controller is typed as `MenubarController` and its options as `MenubarControllerOptions`, both
exported from `@mantine/core`.

## Position

By default, dropdowns are positioned at `bottom-start`. Set the `position` prop to use a different
[Floating UI position](/core/popover/#position-and-placement) for all menus in the bar:

```tsx
import { Menubar } from '@mantine/core';

function Demo() {
  return (
    <Menubar position="bottom-end">
      {/* ...menus */}
    </Menubar>
  );
}
```

To override settings of a single menu, pass [Menu](/core/menu) props to `Menubar.Menu`,
for example `position` or `closeOnItemClick`.

## Accessibility

`Menubar` follows the [WAI-ARIA menubar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/):

- The root element has `role="menubar"`
- Each `Menubar.Target` has `role="menuitem"`, `aria-haspopup="menu"` and `aria-expanded`
- `Menubar.Target` children are used as accessible names of the triggers
