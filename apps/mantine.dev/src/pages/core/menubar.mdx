## Usage

`Menubar` is a desktop-application style menu bar: a horizontal row of top-level menu triggers
(File, Edit, View, …) where each trigger opens a dropdown. Arrow keys move between the top-level
menus, and once one menu is opened, moving to a sibling opens it immediately. `Menubar` follows the
[WAI-ARIA menubar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/).

`Menubar` is built on top of [Menu](/core/menu) – each `Menubar.Menu` is a separate `Menu`
instance, and the dropdown content is composed from the usual `Menu.Item`, `Menu.Divider`,
`Menu.Label`, `Menu.Sub`, `Menu.CheckboxItem` and `Menu.RadioItem` components.

## How it differs from Menu

[Menu](/core/menu) is a single disclosure widget – one target that toggles one dropdown.
`Menubar` coordinates multiple menus:

- The root renders `role="menubar"` and `Menubar.Target` renders `role="menuitem"` triggers with
  `aria-haspopup="menu"`.
- Only one menu in the bar is open at a time. Moving to a sibling while a menu is open switches
  which menu is open.
- The whole bar is a single tab stop (roving `tabindex`) – `Tab` moves focus into and out of the
  menu bar as a single unit, arrow keys move between triggers.

If you need a single dropdown attached to one button, use [Menu](/core/menu) instead.

## Composition

`Menubar` consists of the following components:

- `Menubar` – root element, owns the open/active state of all menus
- `Menubar.Menu` – wraps a single menu, renders a `Menu` instance under the hood
- `Menubar.Target` – top-level trigger button (`role="menuitem"`)
- `Menubar.Dropdown` – dropdown container, accepts the same children as `Menu.Dropdown`

```tsx
import { Menu, Menubar } from '@mantine/core';

function Demo() {
  return (
    <Menubar>
      <Menubar.Menu>
        <Menubar.Target>File</Menubar.Target>
        <Menubar.Dropdown>
          <Menu.Item>New file</Menu.Item>
          <Menu.Item>Open…</Menu.Item>
        </Menubar.Dropdown>
      </Menubar.Menu>

      <Menubar.Menu>
        <Menubar.Target>Edit</Menubar.Target>
        <Menubar.Dropdown>
          <Menu.Item>Undo</Menu.Item>
          <Menu.Item>Redo</Menu.Item>
        </Menubar.Dropdown>
      </Menubar.Menu>
    </Menubar>
  );
}
```

## Trigger and loop

`trigger` controls how a menu is opened when none of the menus is currently open:

- `click` (default) – a menu opens when its target is clicked. Once any menu is open, hovering a
  sibling target switches to it immediately. This matches the behavior of native desktop
  application menu bars.
- `hover` – a menu opens as soon as its target is hovered, even when all menus are closed.

With `trigger="hover"`, a menu opens as soon as its target is hovered and closes when the pointer
leaves the bar:

<Demo data={MenubarDemos.hover} />

`loop` (default `true`) controls whether arrow key navigation wraps around from the last menu to
the first and vice versa.

## Submenus

Use `Menu.Sub` inside `Menubar.Dropdown` to create nested submenus. `ArrowRight` opens a submenu
and moves focus to its first item, `ArrowLeft` closes it and returns focus to the parent item.
See the [Menu submenus documentation](/core/menu/#submenus) for more information.

The [usage demo](#usage) above includes a submenu in the File menu.

## Checkbox and radio items

`Menubar.Dropdown` supports the same selectable items as `Menu`: `Menu.CheckboxItem` for toggles
and `Menu.RadioGroup` with `Menu.RadioItem` for single-choice options. By default, clicking a
checkbox or radio item does not close the menu.

## Controlled

Set `openIndex` and `onOpenChange` to control which menu is open. `openIndex` is the zero-based
index of the opened `Menubar.Menu` (in DOM order) or `null` when all menus are closed:

<Demo data={MenubarDemos.controlled} />

For uncontrolled usage with an initially open menu, use the `defaultOpenIndex` prop instead.

## Controlling with useMenubar

`openIndex`/`defaultOpenIndex`/`onOpenChange` can set which menu is open, and that is all they can
do. They cannot move focus: menus are identified by their DOM order index, so opening a menu from a
keyboard shortcut and landing focus on its first item requires the list of rendered targets, which
only `Menubar` has. Create a controller with the `useMenubar` hook and pass it to `Menubar` with the
`controller` prop to get those actions. The [Controllers](/guides/controllers) guide covers how the
pattern works across all components:

<Demo data={MenubarDemos.controller} />

`useMenubar` accepts the state options that `Menubar` accepts as props, and returns the current
state, actions and queries:

```tsx
import { Menubar, useMenubar } from '@mantine/core';

function Demo() {
  const menubar = useMenubar({
    defaultOpenIndex: 0, // -> uncontrolled initial value
    loop: false, // -> same as the loop prop of Menubar
    // openIndex, onOpenChange -> controlled state, same as on Menubar
  });

  // State
  menubar.openIndex; // -> index of the opened menu, null when all menus are closed
  menubar.activeIndex; // -> index of the menu that holds the menubar tab stop
  menubar.loop; // -> resolved loop option

  // Actions
  menubar.openMenu(1); // -> opens the menu and moves the tab stop to it
  menubar.openMenu(1, 'hover'); // -> same, recorded as opened by hover
  menubar.closeMenu();
  menubar.toggleMenu(1);
  menubar.setOpenIndex(1); // -> sets the index directly, null closes all menus
  menubar.setActiveIndex(1); // -> moves the tab stop without moving DOM focus

  // Focus actions
  menubar.focusMenu(1); // -> moves the tab stop to the menu and focuses its target
  menubar.focusNextMenu(); // -> next enabled menu, respects loop
  menubar.focusPreviousMenu();
  menubar.focusFirstMenu();
  menubar.focusLastMenu();
  menubar.focusMenuItem(1, 'first'); // -> focuses the first item of the opened menu dropdown

  // Queries
  menubar.isMenuOpen(1); // -> boolean
  menubar.getMenuCount(); // -> number of Menubar.Menu components rendered by Menubar
  menubar.getEnabledIndexes(); // -> indexes of the menus that are not disabled
  menubar.getOpenSource(); // -> 'click' | 'hover' | null

  return <Menubar controller={menubar}>{/* menus */}</Menubar>;
}
```

The controller owns the state, so when the `controller` prop is set, the `openIndex`,
`defaultOpenIndex`, `onOpenChange` and `loop` props of `Menubar` are ignored – pass them to
`useMenubar` instead. `trigger` and `position` are not owned by the controller and keep working as
props.

Every query and focus action reads the targets rendered by the associated `Menubar`, which reports
its root element to the controller when it mounts. They are no-op (`getMenuCount()` returns `0`,
`getEnabledIndexes()` returns an empty array) while no `Menubar` is mounted with the controller, and
they are functions rather than fields because the rendered menus are not reactive – reading them
does not re-render the component that owns the controller. One controller drives one `Menubar`:
the root element is replaced rather than accumulated, so two `Menubar` components sharing a
controller report only the menus of the one that mounted last.

`focusMenuItem` focuses an item of a dropdown that is already opened. Call it after `openMenu` – it
waits for the dropdown to render before moving focus, so the two compose into "open this menu and
step into it", which is what a global keyboard shortcut needs.

The controller is typed as `MenubarController` and its options as `MenubarControllerOptions`, both
exported from `@mantine/core`.

## Position

By default, dropdowns are positioned at `bottom-start` relative to their target. Change the
`position` prop to use a different [Floating UI position](/core/popover/#position-and-placement)
for all menus in the bar:

```tsx
import { Menubar } from '@mantine/core';

function Demo() {
  return (
    <Menubar position="bottom-end">
      {/* ...menus */}
    </Menubar>
  );
}
```

Individual menus accept the same props as [Menu](/core/menu) – pass them to `Menubar.Menu` to
override settings for a single menu, for example `position`, `withinPortal`, `closeOnItemClick`,
`shadow`, `width` or `transitionProps`.

## Accessibility

`Menubar` follows the [WAI-ARIA menubar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/):

- The root element has `role="menubar"` and `aria-orientation="horizontal"`.
- Each `Menubar.Target` has `role="menuitem"`, `aria-haspopup="menu"` and `aria-expanded`.
- The menu bar is a single tab stop – only the active trigger is included in the tab sequence,
  arrow keys move focus between the triggers.

The labels you pass to `Menubar.Target` are used as accessible names for the triggers, so make
sure they describe the menu content.
