## Usage

`Editable` displays a value as a preview and switches it to an input for inline editing.
The edit is committed on `Enter` or blur and cancelled on `Escape`:

<Demo data={EditableDemos.usage} />

## Activation mode

`activationMode` prop controls how the preview enters edit mode:

- `focus` (default) – when the preview receives focus (`Tab` or click)
- `click` – on a single click
- `dblclick` – on a double click
- `none` – only with the controller or with `Editable.EditTrigger`

<Demo data={EditableDemos.activation} />

## Submit mode

`submitMode` prop controls what commits the edit. `Escape` cancels the edit in all modes.

- `both` (default) – `Enter` and blur
- `enter` – only `Enter`
- `blur` – only blur
- `none` – only the controller or `Editable.SubmitTrigger`

<Demo data={EditableDemos.submitMode} />

Blur commits the edit when focus leaves `Editable`, including when the browser window
loses focus.

## Select on focus

By default, the input contents are selected when the field enters edit mode.
Set `selectOnFocus={false}` to place the caret at the end of the value instead:

```tsx
import { Editable } from '@mantine/core';

function Demo() {
  return <Editable defaultValue="Project name" selectOnFocus={false} />;
}
```

## Placeholder

Set `placeholder` to display text when the value is empty. It can be a string or an object with
`preview` and `edit` keys to use different text in each mode:

<Demo data={EditableDemos.placeholder} />

## Controlled value

Use `value` and `onChange` props to control the value. `onChange` is called on every keystroke,
`onValueCommit` is called when the edit is confirmed and `onValueRevert` is called when it is
cancelled:

```tsx
import { useState } from 'react';
import { Editable } from '@mantine/core';

function Demo() {
  const [value, setValue] = useState('Project name');
  return (
    <Editable
      value={value}
      onChange={setValue}
      onValueCommit={(committed) => console.log('committed', committed)}
      onValueRevert={(reverted) => console.log('reverted to', reverted)}
    />
  );
}
```

## Controlled editing state

Use `editing` and `onEditingChange` props to control the editing state. Set `defaultEditing` to
start in edit mode in uncontrolled mode:

```tsx
import { useState } from 'react';
import { Editable } from '@mantine/core';

function Demo() {
  const [editing, setEditing] = useState(false);
  return <Editable defaultValue="Project name" editing={editing} onEditingChange={setEditing} />;
}
```

## Multiline

Set `multiline` prop to use a `textarea` instead of an `input`. In multiline mode `Enter` inserts a
new line and the edit is committed with `Cmd`/`Ctrl` + `Enter` or on blur. Set `autosize` to grow
the field with its content, use `minRows` and `maxRows` to limit its size:

<Demo data={EditableDemos.multiline} />

## useEditable hook

`Editable` is built on top of the `useEditable` hook. Use the hook to share one controller
between several components or to build custom edit-in-place UI. It returns the editing
state and actions:

```tsx
import { useEditable } from '@mantine/core';

function Demo() {
  const editable = useEditable({ defaultValue: 'Project name' });

  editable.value; // -> current value
  editable.editing; // -> boolean, true while the field is in edit mode

  editable.edit(); // enters edit mode
  editable.submit(); // commits the edit, calls onValueCommit
  editable.cancel(); // reverts the value to the one it had when editing started, calls onValueRevert
  editable.setValue('New value'); // updates the value

  return null;
}
```

## Controlling with useEditable

To control `Editable` from outside, create a controller with `useEditable` and pass it to the
`controller` prop. When a controller is provided, the props accepted by `useEditable` are
ignored on `Editable` – pass them to `useEditable`.

Buttons outside of `Editable` that call `submit` or `cancel` must call `event.preventDefault()` in
`onMouseDown`. Otherwise the input loses focus and the blur commits the edit before the click
is handled. `submitMode="none"` does not have this issue.

## Custom layout

Pass compound components as children to change the layout. Triggers are displayed only in
the relevant mode: the edit trigger in preview mode, the submit and cancel triggers in edit mode.

<Demo data={EditableDemos.triggers} />

### Compound components

- `Editable.Area` – optional wrapper of the preview and input
- `Editable.Preview` – displays the value in preview mode
- `Editable.Input` – the input displayed in edit mode
- `Editable.Textarea` – the textarea displayed in edit mode, use it instead of `Editable.Input` for multiline values
- `Editable.Control` – wrapper of the triggers
- `Editable.EditTrigger` – enters edit mode
- `Editable.SubmitTrigger` – commits the edit
- `Editable.CancelTrigger` – cancels the edit

## Form field props

`disabled`, `readOnly`, `required`, `maxLength` and `name` props are forwarded to the field.
Set `name` to include the value in native form submission.

In preview mode the value is submitted with a hidden input, which is not validated by the browser:
`required` is enforced only while the field is in edit mode. Validate the value yourself if it
must not be empty.

## Focus management

When the edit is committed or cancelled with the keyboard or with triggers, focus returns to the
preview. Set `finalFocusRef` to move focus to a different element instead. When the edit is
committed by blur, focus stays where the user moved it.

```tsx
import { useRef } from 'react';
import { Button, Editable, Group } from '@mantine/core';

function Demo() {
  const nextRef = useRef<HTMLButtonElement>(null);

  return (
    <Group>
      <Editable defaultValue="Project name" finalFocusRef={nextRef} />
      <Button ref={nextRef}>Next step</Button>
    </Group>
  );
}
```

Moving focus from the input to an element inside `Editable` (for example, pressing `Tab` to reach
`Editable.CancelTrigger`) does not commit the edit.

## Accessibility

The preview has `role="button"` and can be focused and activated with the keyboard, except
when `activationMode="none"`, `disabled` or `readOnly` is set.

The preview is named by its text. If the value can be empty and `placeholder` is not set,
set `aria-label` or `aria-labelledby` on `Editable`:

```tsx
import { Editable } from '@mantine/core';

function Demo() {
  return <Editable aria-label="Project name" />;
}
```

When a trigger renders only an icon, set an `aria-label`:

```tsx
import { Editable } from '@mantine/core';

function Demo() {
  return (
    <Editable defaultValue="Project name" activationMode="none">
      <Editable.Preview />
      <Editable.Input />
      <Editable.EditTrigger aria-label="Edit name">✎</Editable.EditTrigger>
      <Editable.SubmitTrigger aria-label="Save">✓</Editable.SubmitTrigger>
      <Editable.CancelTrigger aria-label="Cancel">✕</Editable.CancelTrigger>
    </Editable>
  );
}
```
