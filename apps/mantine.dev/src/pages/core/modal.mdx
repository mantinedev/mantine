## Fullscreen on small screens

Set the `fullScreenBelow` prop to make the modal fullscreen only when the viewport is narrower
than the given breakpoint:

<Demo data={ModalDemos.fullScreenBelow} />

`fullScreenBelow` accepts a key of `theme.breakpoints` (`xs`, `sm`, `md`, `lg`, `xl`), any CSS length
(for example, `'50em'` or `'800px'`) or a number of pixels. The modal reacts to viewport changes while
it is opened. The `size` prop is ignored while the modal is fullscreen. `fullScreen` takes precedence
over `fullScreenBelow` – it forces fullscreen at any viewport width.

## Initial focus

Modal uses [FocusTrap](/core/focus-trap/) to trap focus. Add the `data-autofocus`
attribute to the element that should receive initial focus.

<Demo data={ModalDemos.initialFocus} />

If you do not want to focus any elements when the modal is opened, use the `FocusTrap.InitialFocus`

If you do not add the `data-autofocus` attribute and do not use `FocusTrap.InitialFocus`,
the modal will focus the first focusable element inside it, which is usually the close button.

## Control behavior

The following props can be used to control `Modal` behavior.
In most cases, it is not recommended to turn these features off –
it will make the component less accessible.

- `trapFocus` – determines whether focus should be trapped inside the modal
- `closeOnEscape` – determines whether the modal should be closed when the `Escape` key is pressed
- `closeOnClickOutside` – determines whether the modal should be closed when the user clicks on the overlay
- `returnFocus` – determines whether focus should be returned to the element that was focused before the modal was opened

## react-remove-scroll settings

`Modal` uses the [react-remove-scroll](https://github.com/theKashey/react-remove-scroll)
package to lock scroll. You can pass props down to the `RemoveScroll` component
with `removeScrollProps`:

```tsx
import { Modal } from '@mantine/core';

function Demo() {
  return (
    <Modal
      removeScrollProps={{ allowPinchZoom: true }}
      opened
      onClose={() => {}}
    />

}
```

## Compound components

You can use the following compound components to have full control over the `Modal` rendering:

- `Modal.Root` – context provider
- `Modal.Overlay` – render [Overlay](/core/overlay/)
- `Modal.Content` – main modal element, should include all modal content
- `Modal.Header` – sticky header, usually contains `Modal.Title` and `Modal.CloseButton`
- `Modal.Title` – `h2` element, the `aria-labelledby` of `Modal.Content` is pointing to this element, usually rendered inside `Modal.Header`
- `Modal.CloseButton` – close button, usually rendered inside `Modal.Header`
- `Modal.Body` – a place for main content, the `aria-describedby` of `Modal.Content` is pointing to this element
- `Modal.Footer` – footer element, usually contains action buttons, pinned to the bottom by default (controlled with `stickyFooter`)

## Modal.Stack

Use the `Modal.Stack` component to render multiple modals at the same time.
`Modal.Stack` keeps track of opened modals, manages z-index values, focus trapping,
and `closeOnEscape` behavior. `Modal.Stack` is designed to be used with the `useModalsStack` hook.

Differences from using multiple `Modal` components:

- `Modal.Stack` manages z-index values – modals that are opened later will always have a higher z-index value regardless of their order in the DOM
- `Modal.Stack` disables focus trap and `Escape` key handling for all modals except the one that is currently opened
- All opened modals stay mounted and visible with a stacked depth effect – modals below the top one are scaled down and offset to create a sense of depth
- Only one overlay is rendered at a time

<Demo data={ModalDemos.stack} />

Modals behind the top one are dimmed by the single overlay and cannot be interacted with –
only the top modal receives pointer events, focus and `Escape` key presses. Set
`withStackTransform={false}` to disable the stacked depth effect – in this case only the top
modal is visible, modals behind it are hidden until the top one is closed.

Use the `maxDepth` prop (default `5`) to control how many stacked modals are visible behind the
top one at the same time:

```tsx
import { Modal, useModalsStack } from '@mantine/core';

function Demo() {
  const stack = useModalsStack(['first', 'second', 'third']);

  return (
    <Modal.Stack maxDepth={3}>
      <Modal {...stack.register('first')}>First</Modal>
      <Modal {...stack.register('second')}>Second</Modal>
      <Modal {...stack.register('third')}>Third</Modal>
    </Modal.Stack>
  );
}
```

Note that `Modal.Stack` can only be used with the `Modal` component. Components built with `Modal.Root`
and other compound components are not compatible with `Modal.Stack`.

All modals rendered inside `Modal.Stack` are a part of the stack, `stackId` prop is required only to
connect modal with the `useModalsStack` hook. To enable stacking for all modals in your application
without `Modal.Stack`, see [shared stack](#shared-stack) section.

## useModalsStack hook

The `useModalsStack` hook provides an easy way to control multiple modals at the same time.
It accepts an array of unique modal IDs and returns an object with the following properties:

```tsx
interface UseModalsStackReturnType<T extends string> {
  // Current opened state of each modal
  state: Record<T, boolean>;

  // Opens modal with the given id
  open: (id: T) => void;

  // Closes modal with the given id
  close: (id: T) => void;

  // Toggles modal with the given id
  toggle: (id: T) => void;

  // Closes all modals within the stack
  closeAll: () => void;

  // Returns props for modal with the given id
  register: (id: T) => {
    opened: boolean;
    onClose: () => void;
    stackId: T;
  };
}
```

Example of using `useModalsStack` with the `Modal` component:

```tsx
import { Modal, useModalsStack } from '@mantine/core';

function Demo() {
  const stack = useModalsStack(['first', 'second']);

  return (
    <>
      <Modal {...stack.register('first')}>First</Modal>
      <Modal {...stack.register('second')}>Second</Modal>
      <Button onClick={() => stack.open('first')}>Open first</Button>
    </>
  );
}
```

## Shared stack

Set `theme.overlayStack` to stack all `Modal` components in your application automatically,
without `Modal.Stack` wrapper and `stackId` prop:

```tsx
import { createTheme, MantineProvider } from '@mantine/core';

const theme = createTheme({
  overlayStack: true,
});

function App() {
  return <MantineProvider theme={theme}>{/* Your app here */}</MantineProvider>;
}
```

<Demo data={ModalDemos.overlayStack} />

With `overlayStack` enabled, all modals join one shared `Modal.Stack`. Any modal that is opened
while another modal is opened is rendered on top of it: z-index, focus trap, `Escape` key handling
and the overlay are managed for the entire application. [Drawer](/core/drawer) components join their
own shared `Drawer.Stack` – modals and drawers are never stacked visually together, but z-index,
focus trap and `Escape` key handling always follow the topmost opened modal or drawer.

`overlayStack` accepts an object to configure the shared stacks:

```tsx
import { createTheme } from '@mantine/core';

const theme = createTheme({
  overlayStack: {
    // Maximum number of stacked modals that remain visible behind the top one, 5 by default
    maxDepth: 3,

    // true by default, false disables the depth effect and shows only the top modal
    withStackTransform: false,
  },
});
```

When `theme.overlayStack` is set, `Modal.Stack` does not create a separate stack – modals
rendered inside it become a part of the shared stack, `maxDepth` and `withStackTransform`
props of `Modal.Stack` are ignored. `useModalsStack` hook can still be used to manage
opened state of several modals.

`stackId` values inside the shared stack are scoped per `Modal.Stack` instance – separate
`Modal.Stack` components may reuse the same ids (for example, two components that both call
`useModalsStack(['first', 'second'])`) without conflicts. `useModalStackContext` called inside such
`Modal.Stack` returns only the modals of that `Modal.Stack`, and its `close` and `closeAll`
handlers do not affect modals of other `Modal.Stack` instances.

Use `useModalStackContext` hook to access the shared stack (or the closest `Modal.Stack`)
from any component:

```tsx
import { Button, useModalStackContext } from '@mantine/core';

function CloseAllButton() {
  const stack = useModalStackContext();
  return <Button onClick={stack.closeAll}>Close all modals ({stack.stack.length})</Button>;
}
```

`useModalStackContext` returns an object with the following properties:

```tsx
interface UseModalStackContextReturnType {
  // Ids of opened modals, the last item is the top modal
  stack: string[];

  // Id of the top modal, undefined if no modals are opened
  currentId: string | undefined;

  // Calls onClose of the modal with the given id
  close: (id: string) => void;

  // Calls onClose of all opened modals, starting from the top one
  closeAll: () => void;
}
```

## Fixed elements offset

The `Modal` component uses the [react-remove-scroll](https://github.com/theKashey/react-remove-scroll)
package to lock scroll. To properly size these elements, add a `className` to them ([documentation](https://github.com/theKashey/react-remove-scroll#positionfixed-elements)):

```tsx
import { RemoveScroll } from '@mantine/core';

function Demo() {
  return (
    <>
      <div className={RemoveScroll.classNames.fullWidth}>
        width: 100%
      </div>
      <div className={RemoveScroll.classNames.zeroRight}>
        right: 0
      </div>
    </>
  );
}
```

## Accessibility

The `Modal` component follows [WAI-ARIA recommendations](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/dialog) on accessibility.

Set the `title` prop to make the component accessible, which will add `aria-labelledby` to the content element:

```tsx
import { Modal } from '@mantine/core';

function Demo() {
  return <Modal title="Modal label" opened onClose={() => {}} />;
}
```

To set the close button's `aria-label`, use `closeButtonProps`:

```tsx
import { Modal } from '@mantine/core';

function Demo() {
  return (
    <Modal
      closeButtonProps={{ 'aria-label': 'Close modal' }}
      opened
      onClose={() => {}}
    />
  );
}
```
