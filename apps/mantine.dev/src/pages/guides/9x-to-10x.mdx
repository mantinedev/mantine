# 9.x → 10.x migration guide

## Update dependencies

Update all `@mantine/*` packages to version 10.x.

## Colors system changes

10.x has a new colors system. Most applications get the new look without code changes.
If you cannot migrate now, use the [v9 opt-out](#v9-opt-out).

### New OKLCH default palettes

Default colors were regenerated in the OKLCH color space. Color names and the number of shades
are the same, color values are different. Review custom colors that were picked to match the
old defaults.

The default dark `primaryShade` is now `7` instead of `8`. To keep the 9.x shade, set
`primaryShade: { light: 6, dark: 8 }` in the theme.

### `--mantine-color-*` CSS variables are now OKLCH strings

`--mantine-color-*` variables now contain `oklch()` strings instead of hex or RGB values.
Update code that reads these variables with `getComputedStyle` and parses them as hex.
The same applies to code that passes them to canvas and other APIs without `oklch` support.

### `autoContrast` now defaults to `true`

Text of filled components is now black or white depending on the background color.
Check the components below in your application, especially with light colors:

To restore the 9.x behavior, disable `autoContrast` in the theme:

```tsx
import { createTheme, MantineProvider } from '@mantine/core';

const theme = createTheme({
  autoContrast: false,
});

function Demo() {
  return <MantineProvider theme={theme}>{/* Your app */}</MantineProvider>;
}
```

Or disable it on individual components:

```tsx
import { Button } from '@mantine/core';

function Demo() {
  return <Button autoContrast={false} color="yellow.3">Label</Button>;
}
```

### Paper is deprecated — use Surface

Replace `Paper` with [Surface](/core/surface), it supports the same props.
`Paper` still works in 10.x and will be removed in 11.0:

```tsx
import { Paper, Surface } from '@mantine/core';

// ❌ Deprecated
function Demo() {
  return <Paper shadow="sm" p="md">Content</Paper>;
}

// ✅ Use Surface instead
function Demo() {
  return <Surface shadow="sm" p="md">Content</Surface>;
}
```

In dark color scheme `Surface` is one shade lighter than `Paper`, and nested surfaces step up
one more level. To keep the `Paper` look, set `level={0}`.

### Darker dark theme

The dark color scheme is darker than in 9.x. If your styles use `dark-N` colors for backgrounds,
test the application in dark color scheme and adjust them. Dropdowns, code elements, scrollbars,
`SegmentedControl` and `contained` `Tabs` have new background colors as well.

Focus rings now use the `--mantine-color-focus-ring` variable instead of the primary filled color.
If you override the focus ring color, override this variable.

### New semantic color variables

Components now use semantic variables such as `--mantine-color-border` instead of `gray-N` and
`dark-N` shades. Overrides of palette shades keep working, the semantic variables reference them.
To change the colors of all components at once, override the semantic variables instead,
see the [colors guide](/theming/colors):

```css
[data-mantine-color-scheme='light'] {
  --mantine-color-border: #d0d0d0;
  --mantine-color-border-subtle: #e8e8e8;
}

[data-mantine-color-scheme='dark'] {
  --mantine-color-border: #404040;
  --mantine-color-border-subtle: #333;
}
```

## Disabled state

Disabled components keep their colors and are displayed with reduced opacity instead of
turning gray. Set `theme.disabledOpacity` to change it:

```tsx
import { createTheme, MantineProvider } from '@mantine/core';

const theme = createTheme({
  disabledOpacity: 0.4,
});

function Demo() {
  return <MantineProvider theme={theme}>{/* Your app */}</MantineProvider>;
}
```

If your styles use the `--mantine-color-disabled`, `--mantine-color-disabled-color` or
`--mantine-color-disabled-border` variables, replace them with the opacity variable.
The same applies to the `disabledBody`, `disabledText` and `disabledBorder` keys of `vars.colors`
in `@mantine/vanilla-extract`:

```css
.custom-control:disabled {
  opacity: var(--mantine-disabled-opacity);
}
```

The [v9 opt-out](#v9-opt-out) does not restore the gray disabled styles.

## Blockquote changes

[Blockquote](/core/blockquote) no longer has a background and rounded corners, the icon is
displayed above the quote and is smaller. The `radius` prop and the `--bq-bg-light`, `--bq-bg-dark`
and `--bq-radius` variables were removed. If you used them, style the `root` element instead:

```tsx
import { Blockquote } from '@mantine/core';

function Demo() {
  return (
    <Blockquote
      styles={{
        root: {
          backgroundColor: 'var(--mantine-color-blue-light)',
          borderRadius: 'var(--mantine-radius-md)',
        },
      }}
    >
      Life is like an npm install – you never know what you are going to get.
    </Blockquote>
  );
}
```

## ColorPicker changes

[ColorPicker](/core/color-picker) and `ColorInput` display 10 swatches per row instead of 7.
Set `swatchesPerRow={7}` to restore the previous layout.

The picker now follows `theme.defaultRadius`. Set `radius` on `ColorPicker` to change it,
`ColorInput` does not pass its `radius` prop to the picker.

## Slider changes

[Slider](/core/slider) and `RangeSlider` thumb is now white with a colored border, and its size
depends on the `size` prop. Set `variant="filled"` to fill the thumb with the slider color and
`thumbSize` to restore the previous size. If you changed `thumb` styles with Styles API, check
that they still look as intended.

## Stepper.Step step, state, allowStepClick and onClick props

If you set `step`, `state`, `allowStepClick` or `onClick` on a `Stepper.Step` inside a
[Stepper](/core/stepper), remove them – `Stepper` ignored them in 9.x and applies them in 10.0:

```tsx
import { Stepper } from '@mantine/core';

function Demo() {
  return (
    <Stepper active={1}>
      {/* This step is now inactive and displays 6 as its icon */}
      <Stepper.Step label="First" step={5} state="stepInactive" />
      <Stepper.Step label="Second" />
    </Stepper>
  );
}
```

Keep them only on steps that should not follow the `active` prop of `Stepper`.

## Timeline data-opposite attribute

If your styles target `[data-opposite]` on the [Timeline](/core/timeline) root element, target the
opposite content instead – `Timeline` no longer sets the attribute:

```css
/* 9.x */
.timeline[data-opposite] {
  /* ... */
}

/* 10.0 */
.timeline:has(.mantine-Timeline-itemOpposite) {
  /* ... */
}
```

## Controller hook types renamed

Rename the imported types of `useTimer`, `useEditable` and `useImageCropper` hooks.
The `useHook.Options` and `useHook.ReturnValue` namespace types were removed as well:

<DataTable
  head={['9.x', '10.x']}
  data={[
    [<Code>UseTimerOptions</Code>, <Code>TimerControllerOptions</Code>],
    [<Code>UseTimerReturnValue</Code>, <Code>TimerController</Code>],
    [<Code>UseEditableOptions</Code>, <Code>EditableControllerOptions</Code>],
    [<Code>UseEditableReturnValue</Code>, <Code>EditableController</Code>],
    [<Code>UseImageCropperOptions</Code>, <Code>ImageCropperControllerOptions</Code>],
    [<Code>UseImageCropperReturnValue</Code>, <Code>ImageCropperController</Code>],
  ]}
/>

The hooks themselves did not change:

```tsx
// 9.x
import type { UseTimerReturnValue } from '@mantine/core';

// 10.x
import type { TimerController } from '@mantine/core';
```

## Tree store prop

Rename the `tree` prop of `Tree` to `store`. The `tree` field of the `renderNode` payload is
renamed to `store` as well, and the `TreeController` type is now `TreeStore`:

```tsx
// 9.x
import { Tree, useTree } from '@mantine/core';

function Demo() {
  const tree = useTree();
  return (
    <Tree
      data={data}
      tree={tree}
      renderNode={({ node, tree }) => (
        <div onClick={() => tree.toggleExpanded(node.value)}>{node.label}</div>
      )}
    />
  );
}

// 10.x
import { Tree, useTree } from '@mantine/core';

function Demo() {
  const store = useTree();
  return (
    <Tree
      data={data}
      store={store}
      renderNode={({ node, store }) => (
        <div onClick={() => store.toggleExpanded(node.value)}>{node.label}</div>
      )}
    />
  );
}
```

## Picker inputs calendar theme defaults

If you set `defaultLevel` or `defaultDate` in theme `defaultProps` of `Calendar` or a picker
component, they no longer apply to the dropdown of picker inputs. Set them on the input instead:

```tsx
import { createTheme } from '@mantine/core';
import { DatePickerInput } from '@mantine/dates';

const theme = createTheme({
  components: {
    DatePickerInput: DatePickerInput.extend({
      defaultProps: { defaultLevel: 'year' },
    }),
  },
});
```

## Picker inputs popoverProps.opened

If you pass `popoverProps.opened` to a picker input or `DateTimePicker`, update it in
`popoverProps.onChange`. It is now called on every open and close, and the input cannot open
its dropdown without it:

```tsx
import { useState } from 'react';
import { DatePickerInput } from '@mantine/dates';

function Demo() {
  const [opened, setOpened] = useState(false);
  return <DatePickerInput popoverProps={{ opened, onChange: setOpened }} />;
}
```

With the `controller` prop, pass `dropdownOpened` and `onDropdownOpenedChange` to the controller
hook instead, `popoverProps.opened` is ignored.

## Picker inputs dropdown type and submit button

Picker inputs and `DateTimePicker` now open in a bottom drawer on small screens, and `onChange`
is called only when the user presses the submit button in the drawer.

- To keep the popover on all screens, set `dropdownType="popover"`
- To call `onChange` on selection, set `applyOnSubmit={false}`

Both props can be set for all components in the theme:

```tsx
import { createTheme } from '@mantine/core';
import { DatePickerInput, DateTimePicker } from '@mantine/dates';

const theme = createTheme({
  components: {
    DatePickerInput: DatePickerInput.extend({
      defaultProps: { dropdownType: 'popover' },
    }),
    DateTimePicker: DateTimePicker.extend({
      defaultProps: { applyOnSubmit: false },
    }),
  },
});
```

## DateTimePicker and InlineDateTimePicker submit button

The submit button is now a `Button` with a text label instead of an `ActionIcon`.
Remove `ActionIcon` specific props from `submitButtonProps`, for example `size="input-sm"`.
To change the label, set `submitButtonLabel` on the component or in `DatesProvider` settings:

```tsx
import { DatesProvider, DateTimePicker } from '@mantine/dates';

function Demo() {
  return (
    <DatesProvider settings={{ submitButtonLabel: 'Apply' }}>
      <DateTimePicker submitButtonProps={{ variant: 'light' }} />
    </DatesProvider>
  );
}
```

## DatesProvider consistentWeeks default

If you want months to have only as many weeks as they need, set `consistentWeeks: false` in
`DatesProvider` – the setting is now `true` by default and every month has 6 weeks in all
calendar components:

```tsx
import { DatesProvider } from '@mantine/dates';

function Demo() {
  return (
    <DatesProvider settings={{ consistentWeeks: false }}>
      {/* Your app here */}
    </DatesProvider>
  );
}
```

If you set `consistentWeeks: true`, you can remove it.

## useMatches options argument

Remove the second argument of `useMatches`. The hook always returns the `base` value on the
server and during hydration:

```tsx
import { useMatches } from '@mantine/core';

// Before
const value = useMatches({ base: 'a', sm: 'b' }, { getInitialValueInEffect: false });

// After
const value = useMatches({ base: 'a', sm: 'b' });
```

## Grid.Col default span

`Grid.Col` without `span` now spans all `columns` of the grid. Before, it always spanned 12 columns, which was half of the row with `columns={24}`. Set `span={12}` to keep the old width in grids with a custom `columns` value.

## useScroller dragHandlers

`useScroller` now tracks dragging on the document, so `dragHandlers` contains only `onMouseDown`. If you passed the handlers one by one, keep `onMouseDown` and remove `onMouseMove`, `onMouseUp` and `onMouseLeave`. Spreading `{...dragHandlers}` works as before. The hook no longer sets the cursor on the container: use the `isDragging` value to set it.

## MaskInput value and onChange

`MaskInput` `value`, `defaultValue` and `onChange` now work with the raw value without the mask. `onChange` receives a string instead of an event:

```tsx
import { MaskInput } from '@mantine/core';

// Before
<MaskInput mask="(999) 999-9999" onChange={(event) => setValue(event.currentTarget.value)} />

// After, value is "1234567890" instead of "(123) 456-7890"
<MaskInput mask="(999) 999-9999" value={value} onChange={setValue} />
```

Use `onChangeRaw` if you need the masked value.

Masked strings are no longer parsed: `value`, `defaultValue` and use-form values (`initialValues`, `form.setFieldValue`, `form.reset`) must be raw. Store `1234567890`, not `(123) 456-7890`. Use `unformatMask` to convert stored masked values. `useMask` `setValue` accepts a raw value as well.

## beforeMaskedStateChange removed

Remove the `beforeMaskedStateChange` option from `useMask` and the prop from `MaskInput`. It was never called. The `MaskState` type is no longer exported.

## TimeInput data-empty attribute

If you set your own `data-empty` attribute on `TimeInput`, rename it. The component now sets
`data-empty` on the input element while it has no value.

## Combobox store listId and selectedOptionIndex

Replace `combobox.listId` and `combobox.selectedOptionIndex` with the `getListId()` and
`getSelectedOptionIndex()` functions:

```tsx
const combobox = useCombobox();

// 9.x
combobox.listId;
combobox.selectedOptionIndex;

// 10.x
combobox.getListId();
combobox.getSelectedOptionIndex();
```

`useVirtualizedCombobox` still accepts the `selectedOptionIndex` option.

## comboboxProps.store in Select, MultiSelect, TagsInput and Autocomplete

`store` passed in `comboboxProps` is ignored. Create the store with the component hook, for
example `useMultiSelect`, and pass it to the `store` prop. It includes all `useCombobox` actions:

```tsx
// 9.x
const combobox = useCombobox();
<MultiSelect data={data} comboboxProps={{ store: combobox }} />;

// 10.x
const store = useMultiSelect();
<MultiSelect data={data} store={store} />;
```

## Controller hooks return a memoized object

`useTimer`, `useEditable`, `useImageCropper` and `usePagination` now return the same object
until the state changes. If you use the returned object as a `useEffect` dependency, depend on
state values instead:

```tsx
const controller = useTimer();

// Ran on every render in 9.x, runs only when the timer state changes in 10.x
useEffect(() => {
  /* ... */
}, [controller]);

// Use this instead
const running = controller.isRunning();

useEffect(() => {
  /* ... */
}, [running]);
```

## ModalBase components removed

If you built a custom dialog with `ModalBase*` components, replace them with
[Modal](/core/modal#compound-components) or `Drawer` compound components:

## Drawer swipe to dismiss

[Drawer](/core/drawer#swipe-to-dismiss) is now closed with a swipe gesture by default.
To disable it, set `withSwipe={false}` on `Drawer` or in the theme:

```tsx
import { createTheme, Drawer } from '@mantine/core';

const theme = createTheme({
  components: {
    Drawer: Drawer.extend({
      defaultProps: { withSwipe: false },
    }),
  },
});
```

If the drawer contains draggable elements, set the `data-drawer-no-swipe` attribute on them
to keep the swipe gesture away from them:

```tsx
import { Drawer } from '@mantine/core';

function Demo() {
  return (
    <Drawer opened onClose={() => {}}>
      <div data-drawer-no-swipe>{/* Draggable content */}</div>
    </Drawer>
  );
}
```

## Uncontrolled mode is the default

`useForm` and `useField` are now uncontrolled by default: the component does not rerender when
the user types. If your form reads `form.values` during render, use `form.useWatchValue('path')`
instead, or set `mode: 'controlled'` to keep the previous behavior:

```tsx
// 9.x
const form = useForm({ initialValues: { name: '' } });
<Text>{form.values.name}</Text>

// 10.x
const form = useForm({ mode: 'controlled', initialValues: { name: '' } });
<Text>{form.values.name}</Text>

// 10.x, uncontrolled
const form = useForm({ initialValues: { name: '' } });
const name = form.useWatchValue('name');
<Text>{name}</Text>
```

See [form modes](/form/uncontrolled) for the differences between the two modes.

## form.key removed

Remove `key={form.key('path')}` from inputs. In lists, use a stable key stored in the list
item, for example a `randomId()`, not the field path:

```tsx
// 9.x
<TextInput key={form.key('name')} {...form.getInputProps('name')} />

// 10.x
<TextInput {...form.getInputProps('name')} />
```

`useField` no longer returns `key`, remove `key={field.key}` the same way. The `Key` type is no longer exported, remove its imports.

## Uncontrolled form inputs receive value

In uncontrolled mode, `getInputProps` now returns `value` and `checked` instead of
`defaultValue` and `defaultChecked`. Change custom inputs and `enhanceGetInputProps` functions
that read `defaultValue` to read `value`.

Set an initial value for every field rendered with an input, otherwise React warns about an
input switching from uncontrolled to controlled.

If your custom input keeps state that `value` cannot express, for example a partially entered
date, clear it with the [use-form-field](/hooks/use-form-field#onexternalwrite) hook when the
form writes the value.

## form.isDirty and form.isTouched in uncontrolled mode

If you read `form.isDirty()` or `form.isTouched()` during render, for example to disable a
submit button, replace the call with the `form.useDirty()` or `form.useTouched()` hook.
In uncontrolled mode the form no longer rerenders when a field becomes dirty:

```tsx
// 9.x
<Button disabled={!form.isDirty()}>Save</Button>

// 10.x
const dirty = form.useDirty();
<Button disabled={!dirty}>Save</Button>
```

Calls in event handlers and `form.onSubmit` do not change.

## Form values are not cloned on every change

Do not mutate the object returned from `form.getValues()` or `form.values`, it is no longer a
copy. Use `form.setFieldValue` or `form.setValues` instead.

## form.setValues clears only errors of changed fields

If you call `form.setValues` after a failed submit and expect all errors to disappear, call
`form.clearErrors()` before it. `form.setValues` now clears errors only of the fields it sets:

```tsx
// 9.x
form.setValues(data);

// 10.x
form.clearErrors();
form.setValues(data);
```

## UseFieldReturnType type parameters

Remove the third type argument of `UseFieldReturnType`:
`UseFieldReturnType<string, 'input', 'uncontrolled'>` becomes `UseFieldReturnType<string, 'input'>`.

## Removed @mantine/form types

If you import `ClearFieldDirty`, `SetFieldTouched`, `SetFieldDirty` or `SetCalculatedFieldDirty`
types, replace them with indexed form types, for example `UseFormReturnType<Values>['setTouched']`.

## v9 opt-out

If your application cannot be migrated now, restore 9.x colors with `v9Theme` and
`v9CssVariablesResolver`:

```tsx
import {
  MantineProvider,
  v9Theme,
  v9CssVariablesResolver,
} from '@mantine/core';

function App() {
  return (
    <MantineProvider
      theme={v9Theme}
      cssVariablesResolver={v9CssVariablesResolver}
    >
      {/* Your app */}
    </MantineProvider>
  );
}
```

`v9Theme` contains 9.x hex colors and sets `autoContrast: false`, `v9CssVariablesResolver`
outputs hex and RGB CSS variables. Both will be removed in 11.0.

## Browser support

The new colors require Chrome and Edge 111, Safari 16.2 or Firefox 113 and later.
To support older browsers, use the [v9 opt-out](#v9-opt-out) or a PostCSS plugin that
converts `oklch` values.
