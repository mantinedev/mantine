## Uncontrolled mode

Uncontrolled mode is the default mode. Form values are stored outside of React state.
The component that calls `useForm` does not rerender when the user types: each input
is subscribed to its own field and rerenders alone. `form.values` is a snapshot from the
last render of the form component, read current values with `form.getValues()`.

The form component still rerenders when:

- an error is set or cleared
- a value is written by the form: `form.setFieldValue`, `form.setValues`, `form.reset`, `form.initialize` and list handlers, except [setFieldValue with forceUpdate: false](/form/values/#setfieldvalue-without-form-rerender)
- a field changes and its input is not subscribed, for example a native `input` element
- `form.submitting` or `form.validating` changes

Example of uncontrolled mode, note that `form.values` in the code block is updated only when the form component rerenders, for example on submit:

## Controlled mode

In controlled mode, form values are stored in React state: `form.values` is updated
on every change and the component that calls `useForm` rerenders with all its children.
Both modes have the same API, set `mode: 'controlled'` for small forms when you render
`form.values` directly:

## form.getValues

`form.getValues()` returns the current values in both modes. `form.values` is a snapshot
from the last render of the form component: in uncontrolled mode it is not updated while
the user types, only when the form rerenders.

```tsx
import { useForm } from '@mantine/form';

const form = useForm({
  initialValues: { name: 'John Doe' },
});

const handleNameChange = () => {
  form.setFieldValue('name', 'Test Name');

  // ❌ form.values is outdated
  console.log(form.values); // { name: 'John Doe' }

  // ✅ form.getValues always returns the latest values
  console.log(form.getValues()); // { name: 'Test Name' }
};
```

`form.getValues()` reads the value, it does not subscribe the component to changes.
In uncontrolled mode, a `useEffect` with `form.getValues()` in dependencies does not
run again when values change because the component does not rerender. Use the
[onValuesChange](/form/watch/#onvalueschange) option or
[form.watch](/form/watch/#formwatch) instead:

```tsx
import { useEffect } from 'react';
import { useForm } from '@mantine/form';

const form = useForm({
  initialValues: { name: '' },
  // ✅ Called on every change
  onValuesChange: (values) => console.log(values),
});

// ❌ Runs only once, the component does not rerender when values change
useEffect(() => {}, [form.getValues()]);
```

## Conditional fields

Rendering a part of the form based on a field value is the most common case where
uncontrolled mode is surprising: `form.getValues()` is read once during render and the
condition never updates. Use [form.useWatchValue](/form/watch/#formusewatchvalue), it
subscribes the component to a single field:

```tsx
import { Checkbox, Collapse, TextInput } from '@mantine/core';
import { useForm } from '@mantine/form';

function Demo() {
  const form = useForm({
    initialValues: { shipsInternationally: false, country: '' },
  });

  // ❌ Does not rerender the component when the checkbox is toggled
  const stale = form.getValues().shipsInternationally;

  // ✅ Rerenders the component when the checkbox is toggled
  const shipsInternationally = form.useWatchValue('shipsInternationally');

  return (
    <>
      <Checkbox
        label="Ships internationally"
        {...form.getInputProps('shipsInternationally', {
          type: 'checkbox',
        })}
      />
      <Collapse expanded={shipsInternationally}>
        <TextInput label="Country" {...form.getInputProps('country')} />
      </Collapse>
    </>
  );
}
```

## Dirty and touched state

`form.isDirty()` and `form.isTouched()` return the current state when called, the form
component does not rerender when it changes. To render dirty or touched state, use
[form.useDirty and form.useTouched](/form/status/#usedirty-and-usetouched-hooks) hooks.

## form.getInputProps

[form.getInputProps](/form/get-input-props/) returns the same props in both modes:
`value` (or `checked`), `onChange`, `onFocus`, `onBlur` and `error`. In uncontrolled mode,
all Mantine inputs are subscribed to their field and receive values written with
`form.setFieldValue`, `form.setValues`, `form.reset` and list handlers without rerendering
the form component. No `key` prop is required:

```tsx
import { Button, TextInput } from '@mantine/core';
import { useForm } from '@mantine/form';

function Demo() {
  const form = useForm({
    initialValues: { text: '' },
  });

  return (
    <>
      <TextInput {...form.getInputProps('text')} />
      <Button onClick={() => form.setFieldValue('text', 'Updated')}>
        Set value
      </Button>
    </>
  );
}
```

Native inputs and third-party components that are not subscribed still receive the new
`value`: the form component rerenders when their field changes, the same way as in
controlled mode. To subscribe a custom component to its field, see
[custom inputs](/form/get-input-props/#custom-inputs).

## One input per field path

Uncontrolled mode has a limitation: bind each field path to a single input. When the same path
is passed to a Mantine input and to a component that is not subscribed (a native input or a
third-party component), the second one is not updated while the user types in the first. If
you need several inputs for the same field, either subscribe every component to the field with
the [use-form-field](/hooks/use-form-field) hook or switch the form to controlled mode:

```tsx
import { TextInput } from '@mantine/core';
import { useForm } from '@mantine/form';

function Demo() {
  const form = useForm({ initialValues: { email: '' } });

  return (
    <>
      <TextInput {...form.getInputProps('email')} />
      {/* Not updated while the user types in TextInput */}
      <input {...form.getInputProps('email')} />
    </>
  );
}
```
