## Usage

Schedule is a unified component that combines all schedule views (Day, Week, Month, Year) with automatic
view switching. Use the view selector in the header to switch between different views.

<Demo data={ScheduleDemos.usage} />

## Controlled state

Control the current view and date externally using the `view`, `onViewChange`, `date`, and `onDateChange` props.
This allows you to build custom navigation or integrate with other components.

<Demo data={ScheduleDemos.controlled} />

## View-specific props

Customize each view by passing view-specific props via `dayViewProps`, `weekViewProps`, `monthViewProps`,
and `yearViewProps`. These props are forwarded to the corresponding view component.

For example, you can set different time ranges for Day and Week views, or customize the first day of week
for Month and Year views.

<Demo data={ScheduleDemos.viewProps} />

## Default view

Set `defaultView` to control which view is shown initially when using uncontrolled mode.

## Custom header

You can build a custom header using `ScheduleHeader` compound components combined with your own controls.
Disable the default header on all views by passing `withHeader={false}` through view-specific props.

## Agenda view

Set `withAgenda` prop to display an "Agenda" button in the header of DayView, WeekView
and MonthView. When clicked, it opens an `AgendaView` showing events for the currently
visible date range.

<Demo data={ScheduleDemos.withAgenda} />

## Drag and drop

Enable event drag and drop by setting `withEventsDragAndDrop` prop. Events can be dragged
to different time slots and days across all views.

<Demo data={ScheduleDemos.dragDrop} />

## Create and update events

Set `withDragSlotSelect` prop to allow users to drag across time slots or day cells to select a range.
When the drag ends, the `onSlotDragEnd` callback is called with the range start and end dates.
Combined with `onTimeSlotClick`, `onAllDaySlotClick`, `onDayClick`, and `onEventClick` callbacks,
this enables a complete event creation and editing experience across all views.

<Demo data={ScheduleDemos.eventForm} />

## External drag and drop

Use `onExternalEventDrop` to allow dragging items from outside the component into
the schedule. External items must set data in `dataTransfer` during their `onDragStart`.
The callback receives the `DataTransfer` object and the drop target datetime.

<Demo data={ScheduleDemos.externalDragDrop} />

## Bidirectional drag and drop

Combine `onExternalEventDrop` with `withEventsDragAndDrop` to enable bidirectional
drag and drop. Items dragged from the sidebar are removed from the list and added
to the schedule. Events dragged from the schedule back to the sidebar are removed
from the schedule. The schedule sets `application/json` with `{ eventId }` in
`dataTransfer` when an event is dragged, which the sidebar drop zone reads to
identify the event.

<Demo data={ScheduleDemos.bidirectionalDragDrop} />

## Event resize

Enable event resizing by setting `withEventResize` prop. Users can drag the top or bottom
edge of an event to adjust its start or end time. Use `onEventResize` callback to handle
the resize. Event resize works in both Day and Week views and can be combined with drag and drop.

<Demo data={ScheduleDemos.eventResize} />

## Drop validation

By default a drop or resize is always committed and the application decides in `onEventDrop` /
`onEventResize` whether to accept it. That produces a snap-back with no explanation. Use the
validation props to reject a placement **before** it is committed, based on where the event is
being dropped rather than on which event is being dragged:

<DataTable
  head={['Prop', 'Description']}
  data={[
    [
      '`preventEventOverlap`',
      'Rejects placements that would overlap another event. Pass a function to decide per pair of events.',
    ],
    [
      '`canDropEvent`',
      'Called while an event is dragged over a target and again before the drop is committed, return `false` to reject the drop',
    ],
    [
      '`canResizeEventTo`',
      'Called on every pointer move while an event is resized and again before the resize is committed, return `false` to reject the new size',
    ],
    [
      '`canDropExternalEvent`',
      'Called while an external item is dragged over a target and again before the drop is committed, return `false` to reject the drop',
    ],
    ['`onEventPlacementRejected`', 'Called when a drop or resize is rejected'],
  ]}
/>

The checks compose: a placement is allowed only when the overlap check passes **and** the matching
callback returns a value other than `false`. The overlap check runs first, so `onEventPlacementRejected`
can report `conflicts` without your code repeating the work.

The callbacks and the function form of `preventEventOverlap` run at `dragover` / `pointermove`
frequency to compute the live feedback described below, so they must be pure and cheap. Do not show
notifications, update state or send requests from them – use `onEventPlacementRejected` for that.

Live feedback before the pointer is released is limited to two places. The drag ghost gets
`data-invalid` while it is over an invalid target – the ghost is only rendered when `eventDragInterval`
is set, so without it the slot highlight looks the same over a valid and an invalid target. A resizing
event gets `data-invalid` on the `event` selector in every view that supports resize. `MonthView`,
`ResourcesMonthView` and the `WeekView` all-day row have no drag ghost and give no pre-drop feedback:
there the rejection is only reported through `onEventPlacementRejected` on drop. The drop is still
allowed at the browser level – marking it as not-allowed would make the browser skip the `drop` event
entirely and `onEventPlacementRejected` would never fire.

<Demo data={WeekViewDemos.preventEventOverlap} />

### What counts as a conflict

`preventEventOverlap` compares the candidate range against the events the view has expanded. These
are excluded from the conflict set:

- The moving event itself, matched by `id`, and other occurrences of the same recurring series that
  share its `recurrenceId`.
- Events with `display: 'background'` – they are a shading layer, not bookings.
- All-day events when the moving event is timed, and timed events when the moving event is all-day.

Touching is not overlapping: an event ending at 10:00 and one starting at 10:00 do not conflict.

In `Resources*` views the conflict set is scoped to the **target** resource, so moving an event to a
different resource row is checked against that row rather than the one it came from.

`preventEventOverlap` is a **view-local** guard: it only sees events the current view has expanded, so
a conflict outside the visible range is not detected. An application with authoritative data should
still validate in `onEventDrop`.

### Blocking drops onto closed hours

Background events are deliberately not part of the conflict set. To block drops onto a closed or
blocked zone, use `canDropEvent` with the exported `isEventsOverlap` helper:

```tsx
import { isEventsOverlap, ScheduleEventData } from '@mantine/schedule';

<WeekView
  canDropEvent={({ start, end }) =>
    !closedZones.some((zone) => isEventsOverlap({ start, end } as ScheduleEventData, zone))
  }
/>;
```

### Rejection data

`onEventPlacementRejected` receives a discriminated union keyed on `action`. Every member carries
`start`, `conflicts`, `reason` (`'overlap'` when the overlap check found a conflict, `'rejected'` when
a callback returned `false`) and, in `Resources*` views, `resourceId` – the target resource for `drop`
and `external-drop`, the event's own resource for `resize`:

<DataTable
  head={['action', 'Extra fields']}
  data={[
    ['`drop`', '`event`, `end`'],
    ['`resize`', '`event`, `end`, `edge`'],
    ['`external-drop`', '`dataTransfer`'],
  ]}
/>

External drops carry no `event` and no `end` – `onExternalEventDrop` only produces a single datetime
and the schedule does not know the duration of an external item – so `preventEventOverlap` does not
apply to them, their `reason` is always `'rejected'` and `conflicts` is always empty. Note that
`dataTransfer` data cannot be read while a drag is in progress, only `dataTransfer.types` is available
to `canDropExternalEvent`.
