## Column reorder

Pass `withColumnReorder` to `useDataGrid` to enable column reordering. Users drag a column header
with the pointer (mouse, pen or touch): the drag starts after 4px of movement so a plain click
still sorts, a ghost of the header label follows the pointer, the source header is dimmed, and a
2px drop line with a dot marks the target edge, decided by the pointer position relative to the
middle of the hovered header.

<Demo data={DataGridDemos.columnReorder} />

Valid targets are data columns in the same pin region and, under header groups, in the same parent
group; utility columns and group headers are never targets. Dropping writes `columnOrder` through
the store, where utility columns are always kept first. With `withColumnMenu` the column menu adds
**Move left** and **Move right** items, which reorder from the keyboard with the same target rules
(they follow the visual direction under RTL). There is no auto-scroll while dragging.

Use `columnOrder` and `onColumnOrderChange` for controlled state. Reset the column order
with `store.table.setColumnOrder([])`; the store re-prepends any utility column id missing from
the order, also when it restores persisted state.

## Header groups

Group columns under shared headers by nesting column definitions. Use the `columns` property
on a column definition to create header groups. Group header cells carry `data-header-group`,
draw a divider at their inline end (placeholders carry `data-placeholder` and draw nothing), keep
their label start-aligned and take the same height as every other header row. Group headers keep
their resize handle (resizing a group resizes its leaves proportionally) but have no sort button,
column menu or drag behavior.

## Column alignment

Set `meta.align` (`'start' | 'center' | 'end'`, default `start`) on a column to align its header,
body and tfoot cells; the value is reflected as `data-align` on the cells. End-aligned columns use
tabular figures automatically, which is the intended setting for numbers:

```tsx
const columns = [
  { accessorKey: 'name', header: 'Name' },
  { accessorKey: 'status', header: 'Status', meta: { align: 'center' } },
  { accessorKey: 'amount', header: 'Amount', meta: { align: 'end' } },
];
```

## Utility columns

Features that need their own column inject a TanStack display column at the start of the grid:
`__reorder__` (`withRowReorder`), `__select__` (`withRowSelection`), `__expand__`
(`withRowExpansion` without tree data) and `__rowNumber__` (`withRowNumbers`), in that order. They
carry `meta.utility`, cannot be sorted, filtered, resized or hidden through the UI, are excluded
from export and the column menu, are forced to the start of `columnPinning.start` under column
pinning, and get their width from the grid `size` (overridable through `columnSizing`). The ids are
exported as `UTILITY_COLUMN_IDS`, and code that iterates `table.getAllColumns()` should skip
columns with `meta.utility`.

## Cell spanning

Set `spanRows: true` on a column definition to merge adjacent rows that share the same value for
that column into a single vertically spanning cell. Spans are recomputed from the rows that are
actually rendered, so sorting, filtering and pagination only change which rows are adjacent — a run
never crosses a page boundary, a pinned-row section, or a grouped row.

<Demo data={DataGridDemos.cellSpanning} />

Pass a predicate instead of `true` to decide whether a row joins the run anchored at `anchorRow`:

```tsx
const columns = [
  {
    accessorKey: 'startDate',
    header: 'Start Date',
    spanRows: ({ anchorValue, value }) =>
      new Date(anchorValue).getFullYear() === new Date(value).getFullYear(),
  },
];
```

Use `spanColumns` to make a cell span several columns in a given row. Return `1` or less for no
span, or `Infinity` for the rest of the cell's pinned region:

```tsx
const columns = [
  {
    accessorKey: 'label',
    header: 'Label',
    spanColumns: ({ row }) => (row.original.isSummary ? Infinity : 1),
  },
];
```

By default nullish values are not merged. Set `enableCellSpanning: false` on `tableOptions` to turn
spanning off for the whole grid, or `enableCellSpanning: false` on a column to exclude it.

Cell spanning is not applied when virtualization is enabled — the virtualized renderer positions every
cell independently, so `spanRows` and `spanColumns` are ignored for grids that use `virtualize`.
