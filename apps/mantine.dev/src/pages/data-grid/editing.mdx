## Cell editing

Set `editingMode="cell"` in `useDataGrid` to enable inline cell editing. Double-click a cell
(or press `Enter` / `F2` on a focused row) to open its editor. Press `Enter` to save or `Escape`
to cancel; moving focus out of the editor also saves. The `onEditSave` option of `useDataGrid`
receives the updated row:

<Demo data={DataGridDemos.cellEditing} />

## Row editing

Set `editingMode="row"` to edit every editable cell of a row at once. Row editing is started from
an actions column that you declare with `meta.type: 'actions'`: its cell reads
`row.getIsEditing()` and calls `row.startEditing()`, `row.saveEditing()` and
`row.cancelEditing()`. Clicking outside the row saves it, `Escape` cancels, `Tab` and
`Shift + Tab` move between the editors of the row:

<Demo data={DataGridDemos.rowEditing} />

Set `withFloatingEditActions` prop on `DataGrid` to render a floating Save / Cancel pill next to
the row being edited instead of (or in addition to) an actions column. The button labels come
from the `saveRow` and `cancelRow` labels.

The editing state is exposed as `store.editing` and can be driven imperatively with
`store.table.startEditing(rowId, columnId?)`, `store.table.saveEditing()` and
`store.table.cancelEditing()`.

## Modal editing

For complex edit forms, handle `onRowDoubleClick` to open a modal instead of using inline editing.
This approach gives full control over the edit UI and validation flow.

```tsx
<DataGrid
  data={data}
  columns={columns}
  onRowDoubleClick={(row) => {
    setEditingRow(row.original);
    openModal();
  }}
/>
```

## Disabling editing per column

Set `meta.disableEditing: true` on any column definition to prevent that column from entering edit
mode when the grid is in `cell` or `row` editing mode:

```tsx
const columns = [
  { accessorKey: 'id', header: 'ID', meta: { disableEditing: true } },
  { accessorKey: 'firstName', header: 'First Name' },
  { accessorKey: 'department', header: 'Department' },
];
```

Read-only columns like IDs or computed fields should use this flag so users cannot accidentally
modify them. Utility columns, display columns and the actions column are never editable.

## Validation

Add `meta.validate` to a column to validate drafts before they are saved. A non-empty return value
marks the editor as invalid, shows the message in a tooltip and blocks the save until the value
changes:

```tsx
const columns = [
  {
    accessorKey: 'salary',
    header: 'Salary',
    meta: {
      validate: (value) => (Number(value) < 0 ? 'Salary cannot be negative' : null),
    },
  },
];
```

Rejecting the promise returned from `onEditSave` keeps the editor open with the drafts and marks
it invalid until the next change; use `onEditSaveError` to report the error.

## Cell status

Use `getCellStatus` to tint body cells that need attention, for example rows that have unsaved
changes or values that failed a server-side check. Return `dirty` or `invalid`; the colors are
controlled by the `--dg-dirty-color` and `--dg-invalid-color` CSS variables:

```tsx
const store = useDataGrid({
  data,
  columns,
  getCellStatus: ({ row, columnId }) =>
    pendingChanges.has(`${row.id}:${columnId}`) ? 'dirty' : undefined,
});
```
