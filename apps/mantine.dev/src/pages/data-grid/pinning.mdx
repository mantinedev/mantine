## keepPinnedRows

By default, pinned rows remain visible even when they would normally be filtered out or
paginated away. Set `keepPinnedRows: false` in `useDataGrid` to allow pinned rows to be
hidden by filters and pagination.

```tsx
const store = useDataGrid({
  data,
  columns,
  rowPinning: { top: ['1'], bottom: [] },
  keepPinnedRows: false,
  getRowId: (row) => row.id,
});
```

## Per-row pinning control

Use `enableRowPinning` as a function to control which rows can be pinned:

```tsx
const store = useDataGrid({
  data,
  columns,
  rowPinning: { top: [], bottom: [] },
  enableRowPinning: (row) => row.original.status === 'active',
  getRowId: (row) => row.id,
});
```

## Controlled pinning state

Both column and row pinning support controlled state via `columnPinning`/`onColumnPinningChange`
and `rowPinning`/`onRowPinningChange`. Access current state directly from the store:

```tsx
const store = useDataGrid({ data, columns, columnPinning, onColumnPinningChange });

// Read current state
store.columnPinning // { start: ['firstName'], end: [] }
store.rowPinning    // { top: ['1'], bottom: [] }
```

## Sticky positioning design

DataGrid implements column pinning with CSS `position: sticky` on individual `<th>` and `<td>`
elements. This keeps the DOM in a single flat table structure, which preserves native accessibility
semantics and avoids the synchronization overhead of TanStack's split-table rendering approach
(where pinned and non-pinned columns are rendered in separate `<table>` elements). The tradeoff
is that row heights must remain consistent across all columns, which is the standard case for
data grids.

## Limitations

Row pinning is not supported when `virtualize` includes rows. Virtualized mode uses a
different rendering path for performance, and row pinning requires the standard table body renderer.
Column pinning works with both standard and virtualized grids.
