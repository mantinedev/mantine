## Column pinning

Pin columns to the start or end edge of the grid so they remain visible while scrolling
horizontally. Pass `columnPinning` to `useDataGrid` with `start` and `end` arrays of column IDs.

<Demo data={DataGridDemos.columnPinning} />

Pinned cells carry `data-pinned="start"` or `data-pinned="end"` on the `th` and `td`; the last
pinned cell on each side adds `data-pinned-edge`, draws a 1px divider, and shows a shadow only while
the grid is scrolled away from that side (root `data-overflow-start` / `data-overflow-end`). The
shadow is not colorable. Utility columns (selection, expand, row numbers, reorder) are always
pinned first and cannot be unpinned, so the pinned edge lands after the last pinned data column.

## Interactive column pinning

Use controlled `columnPinning` and `onColumnPinningChange` to let users pin and unpin
columns dynamically. With `withColumnMenu` on `DataGrid`, every column gets **Pin to left** /
**Pin to right** / **Unpin** items in its header menu.

## Row pinning

Pin rows to the top or bottom of the grid so they remain visible while scrolling vertically.
Pass `rowPinning` to `useDataGrid` with arrays of row IDs (from `getRowId`) to pin. Pinned rows
render in their own `tbody` with `data-pinned="top"` / `data-pinned="bottom"` (mirrored on each
`tr`), redraw their rules, take no stripe and no row number, and hover and select normally.

<Demo data={DataGridDemos.rowPinning} />

## Interactive row pinning

## Pinning with header groups

Column pinning works with grouped headers. A group header is pinned when every visible leaf column
under it is pinned to the same side; a group whose leaves are split between pinned and unpinned
columns is rendered unpinned.

<Demo data={DataGridDemos.pinningWithGroups} />

## Sticky header

Set `stickyHeader` on `DataGrid` to keep the header visible while the page scrolls. Every header
row takes the body background and redraws its rule, and pinned header cells stay above the body.
`stickyHeaderOffset` (a number in px, converted to rem, or any CSS length) sets where the header
sticks, for example under a fixed app header:

```tsx
<DataGrid store={store} stickyHeader stickyHeaderOffset={60} />
```

Top-pinned rows stick right under the sticky header. The virtualized body scrolls inside its own
container, so its header is always sticky at the top of that container and `stickyHeaderOffset`
does not apply to it.

## keepPinnedRows

By default, pinned rows remain visible even when they would normally be filtered out or
paginated away. Set `keepPinnedRows: false` in `useDataGrid` to allow pinned rows to be
hidden by filters and pagination.

```tsx
const store = useDataGrid({
  data,
  columns,
  rowPinning: { top: ['1'], bottom: [] },
  keepPinnedRows: false,
  getRowId: (row) => row.id,
});
```

## Per-row pinning control

Use `enableRowPinning` as a function to control which rows can be pinned:

```tsx
const store = useDataGrid({
  data,
  columns,
  rowPinning: { top: [], bottom: [] },
  enableRowPinning: (row) => row.original.status === 'active',
  getRowId: (row) => row.id,
});
```

## Controlled pinning state

Both column and row pinning support controlled state via `columnPinning`/`onColumnPinningChange`
and `rowPinning`/`onRowPinningChange`. Access current state directly from the store:

```tsx
const store = useDataGrid({ data, columns, columnPinning, onColumnPinningChange });

// Read current state
store.getColumnPinning() // { start: ['firstName'], end: [] }
store.getRowPinning()    // { top: ['1'], bottom: [] }
```

## Sticky positioning design

DataGrid implements column pinning with CSS `position: sticky` on individual `<th>` and `<td>`
elements. This keeps the DOM in a single flat table structure, which preserves native accessibility
semantics and avoids the synchronization overhead of TanStack's split-table rendering approach
(where pinned and non-pinned columns are rendered in separate `<table>` elements). Every pinned
cell gets its offset from a private CSS variable and inherits the background of its row, so stripes,
hover and selection show through; under column pinning rows are painted with the body color to
cover the scrolling cells behind them.

## Limitations

- A grid rendered on a tinted surface: rows under column pinning are opaque in `--mantine-color-body`, so pinned cells cover a colored background. Override the row background through the Styles API if the grid sits on a tinted panel.
- Row pinning is not supported with any `virtualize` value: it is turned off with a warning in development. Column pinning works with both standard and virtualized grids.
