## Frame

The grid is a framed surface: `withTableBorder` (default `true`) draws a 1px `--dg-border-color`
border around the toolbar, the table and the footer, and `radius` (default `theme.defaultRadius`)
rounds it. `withTableBorder={false}` removes the border and the radius only; the toolbar and footer
rules stay. The header sits on the page surface with no tint, weight 600 and the body font size.

<Demo data={DataGridDemos.frame} />

`borderColor` changes the frame, header and footer rule color; it accepts a key of `theme.colors`
or any valid CSS color.

## Size

`size` is a `useDataGrid` option (`'xs' | 'sm' | 'md' | 'lg' | 'xl'`, default `sm`) exposed as
`store.getSize()` / `store.setSize` and persisted by `useDataGridState` under the `size` key. It sets the
font size, row and header height, cell padding, the checkbox / radio size, the icon size and the
footer height, and cascades a **control size** to the chrome (`store.getControlSize()`: `xs` for `xs` /
`sm` grids, `sm` for `md`, `md` for `lg` / `xl`) that the toolbar, selection bar, footer and loading
overlay use. Pass `store.getControlSize()` to your own buttons and inputs inside the grid so they match.

## Styles API

DataGrid supports the standard Mantine `classNames` and `styles` props to customize individual parts
of the component. Target any selector from the Styles API table on the [DataGrid](/data-grid/data-grid)
component page. Every look is keyed on data attributes on the root (`data-size`, `data-list-view`,
`data-loading-variant`, ...), rows (`data-selected`, `data-striped`, `data-group-row`,
`data-expanded`, `data-editing`, `data-pinned`, ...) and cells (`data-align`, `data-pinned`,
`data-dirty`, ...), so one rule set serves the table body and the virtualized body.

## Compound components

DataGrid renders a default layout when no children are provided. For custom layouts, use the compound
component API to compose the grid from individual parts. Children render inside the frame in a
fixed order: the toolbar slot (toolbar or selection bar), the body, then everything else. The table
itself (header, body and `<tfoot>`) is always rendered by the grid, customize it with the Styles API
selectors (`thead`, `tbody`, `tfoot`, `tr`, `th`, `td`, ...).

<Demo data={DataGridDemos.compoundComponents} />

Available compound components:

- `DataGrid.Toolbar` -- chrome bar above the table, renders global filter, column visibility toggle and export button when empty
- `DataGrid.GlobalFilter` -- global search input
- `DataGrid.ColumnVisibilityToggle` -- labeled `Columns` menu button
- `DataGrid.ExportButton` -- export menu (CSV, Excel, print, copy to clipboard)
- `DataGrid.RowCount` -- total / filtered row count text
- `DataGrid.SelectionBar` -- bulk actions bar shown in the toolbar slot while rows are selected
- `DataGrid.Footer` -- chrome bar below the table with status text, page size select and pagination
- `DataGrid.ColumnMenu` -- column menu button for custom header cells

## Toolbar

An empty `<DataGrid.Toolbar />` renders the global filter (with `withGlobalFilter`), a spacer,
the column visibility toggle (with `withColumnVisibility`) and the export button. Any children
replace this default. The bar wraps its controls, keeps `10px 12px` padding and an 8px gap at every
size, and draws a 1px bottom rule. Controls take their size from `store.getControlSize()`, use it for
your own buttons to match; a `div` with `flex: 1` is the spacer.

<Demo data={DataGridDemos.toolbarComposed} />

`DataGrid.GlobalFilter` accepts `placeholder` and `textInputProps`; `DataGrid.RowCount` renders
`18 rows` (the `rowCount` label) or `5 of 18 rows` (`rowCountFiltered`) from the filtered row model
and never the selected count.

## Export button

`DataGrid.ExportButton` opens a menu with CSV, Excel, print and copy-to-clipboard items backed by
the `exportToCsv`, `exportToExcel`, `exportToPrint` and `copyToClipboard` utilities. `formats`
picks and orders the items (a single format renders a plain button), `fileName` (default `data`)
names the downloaded file, `rows` (`'all' | 'filtered' | 'selected' | 'page'`, default `all`) and
`columns` (`'visible' | 'all' | string[]`, default `visible`) scope every format, and
`csvOptions` / `excelOptions` / `printOptions` / `copyOptions` are passed to the matching utility.
`onExport(format)` is called after an export runs, `children` replaces the button label and
`menuProps` configures the menu. Utility columns, actions columns and columns with
`meta.disableExport` are never exported.

`all` exports every data row (ignoring filters) and `filtered` exports the rows that pass the
current filters; both follow the current sort order and skip pagination, group rows and tree
sub-rows. While rows are grouped, `filtered` lists the data rows in the grouped display order (rows
of the first group, then the next group, sorted within each group), whereas `all` is a flat sort of
every data row that ignores grouping. `page` exports the rows of the current page as displayed.

<Demo data={DataGridDemos.exportButton} />

## Selection bar

`DataGrid.SelectionBar` is a sibling of `DataGrid.Toolbar`. While `rowSelection` is not empty the
grid renders it in the toolbar slot instead of the toolbar (the root carries
`data-selection-bar-visible`): the selected count (`selectionBarSelected` label, counted from the
selection state), your bulk action controls as `children`, and a close button that clears the
selection (`selectionBarClear` label). It shares the toolbar's padding and gap, so controls sized
with `store.getControlSize()` line up with the toolbar. Without a toolbar the grid grows by one bar
while the selection is active.

<Demo data={DataGridDemos.selectionBar} />

Pass `floating` to render the bar above the grid content instead, centered near the bottom of the
frame and above `DataGrid.Footer` (through `--dg-footer-height`) while the toolbar stays visible:

<Demo data={DataGridDemos.selectionBarFloating} />

`withCloseButton={false}` removes the close button and `closeButtonProps` configures it; a custom
`onClick` runs before the selection is cleared.

## Footer

`DataGrid.Footer` renders the status text, the page size select and pagination controls in one bar
at the bottom of the frame; see [Pagination](/data-grid/pagination) for every option.

## Column menu

Set `withColumnMenu` on `DataGrid` to render a menu button in every data column header, at the
inline end of the cell after the label, so it never triggers a sort. The button is revealed when
the header is hovered or focused and while the menu is open (always visible on touch devices). Its
items depend on the store features and the column's `enable*` flags: sort ascending / descending /
clear sort (`enableSorting`), move left / right (`withColumnReorder`), pin / unpin
(`withColumnPinning`), hide (`withColumnVisibility` and `enableHiding`), group / ungroup
(`withGrouping`) and reset size (`withColumnResizing`). A column whose menu would be empty renders no
button; utility and actions columns never do. `columnMenuItems` appends your own items after a
divider, and `meta.disableColumnMenu` hides the menu for one column:

<Demo data={DataGridDemos.columnMenu} />

`DataGrid.ColumnMenu` is the component behind the button. To render the column menu inside your
own header cell, pass the `column` instance from the header context; `children` are appended after
the built-in items and `menuProps` configures the menu:

```tsx
{
  accessorKey: 'name',
  header: ({ column }) => (
    <Group justify="space-between" wrap="nowrap">
      Name
      <DataGrid.ColumnMenu column={column}>
        <Menu.Item>Custom item</Menu.Item>
      </DataGrid.ColumnMenu>
    </Group>
  ),
}
```

## State persistence

Save and restore grid state using the store. Access current state directly from `store.getSorting()`,
`store.getColumnFilters()`, `store.getPagination()`, `store.getSize()`, etc.

```tsx
import { useState, useEffect } from 'react';
import { SortingState } from '@tanstack/react-table';
import { DataGrid, useDataGrid } from '@mantine/data-grid';

const STORAGE_KEY = 'my-grid-state';

function Demo() {
  const [sorting, setSorting] = useState<SortingState>(() => {
    const saved = localStorage.getItem(STORAGE_KEY);
    return saved ? JSON.parse(saved).sorting : [];
  });

  useEffect(() => {
    localStorage.setItem(STORAGE_KEY, JSON.stringify({ sorting }));
  }, [sorting]);

  const store = useDataGrid({
    data,
    columns,
    sorting,
    onSortingChange: setSorting,
  });

  return <DataGrid store={store} />;
}
```

### useDataGridState

`useDataGridState` persists the selected state keys of a store to `localStorage` (writes are debounced)
and restores them on mount and whenever `stateStorageKey` changes. Pass the store returned by
`useDataGrid`; `size` is read from and restored into the store as well:

```tsx
import { DataGrid, useDataGrid, useDataGridState } from '@mantine/data-grid';

function Demo() {
  const store = useDataGrid({ data, columns, withSorting: true, withColumnReorder: true });

  useDataGridState({
    store,
    stateStorageKey: 'my-grid-state',
    persistedState: ['sorting', 'columnOrder', 'columnVisibility', 'size'],
  });

  return <DataGrid store={store} />;
}
```

`columnOrder` is saved as `store.columnOrder`, so the display-only position of grouped columns is
never persisted.

## Custom storage

For session storage, URL search params, or server-side persistence, implement the same pattern
with your preferred storage mechanism. The controlled state options in `useDataGrid` accept any state source.

## Theme integration

Use `createTheme` with `DataGrid.extend` to apply default props and class names globally. This
removes the need to repeat props on every `<DataGrid>` usage in your app:

```tsx
import { createTheme } from '@mantine/core';
import { DataGrid } from '@mantine/data-grid';

const theme = createTheme({
  components: {
    DataGrid: DataGrid.extend({
      defaultProps: { withRowBorders: 'subtle', highlightOnHover: true, radius: 'md' },
      classNames: { root: 'my-grid-root' },
    }),
  },
});
```

## Dark mode

DataGrid automatically adapts to the active Mantine color scheme. Border, stripe, hover, and
selected-row colors all derive from Mantine CSS variables, so switching between light and dark
mode requires no additional configuration.

## ScrollArea configuration

DataGrid wraps the table in a `ScrollArea` by default (`scrollbarSize={4}`, horizontal scrollbar
inside the frame under the last row). Pass `scrollAreaProps` to configure it, or set
`withScrollArea={false}` to handle overflow yourself. The grid attaches its own `viewportRef`, so
`scrollAreaProps.viewportRef` overrides the ref the grid uses for scrolling and pinned-column
shadows; `withScrollArea` is ignored under `virtualize` and in list view.

```tsx
<DataGrid
  store={store}
  scrollAreaProps={{ type: 'always', offsetScrollbars: true }}
/>
```

## TanStack passthrough

The `tableOptions` option in `useDataGrid` provides an escape hatch to the underlying TanStack Table
instance. Any option not covered by the store can be passed directly.

```tsx
const store = useDataGrid({
  data,
  columns,
  tableOptions: {
    enableMultiSort: true,
    maxMultiSortColCount: 3,
    sortDescFirst: false,
    debugTable: process.env.NODE_ENV === 'development',
  },
});
```
