## virtualize prop

The `virtualize` prop controls which axis is virtualized. Pass one of the following values:

```tsx
<DataGrid store={store} virtualize="rows" height={500} />
<DataGrid store={store} virtualize="columns" height={500} />
<DataGrid store={store} virtualize="rows,columns" height={500} />
```

The `height` prop is required for all virtualization modes so the grid has a bounded scroll container.

## Basic virtualization

Set `virtualize="rows"` to enable row virtualization for large datasets. When virtualization is enabled,
only the rows visible in the viewport are rendered to the DOM. The `height` prop is required to define the
scrollable container size.

## Row height estimate

The virtualized body needs an estimated height per row before it measures the rendered rows. The
estimate is resolved in this order, first hit wins:

1. `virtualScrollConfig.estimateSize(index)`
2. `getRowHeight(row)` when it returns a number
3. `estimateRowHeight`
4. the row height of the current grid `size` (`32px` at `sm`)

Row height is a minimum in the table body and an estimate in the virtualized body: rows are
measured after render, so wrapped content still displays correctly.

## Virtual scroll config

Fine-tune virtual scroll behavior with the `virtualScrollConfig` prop:

- `overscan` -- number of rows rendered above and below the visible area (default: `5`)
- `estimateSize` -- function returning the estimated row height in pixels

```tsx
<DataGrid
  data={data}
  virtualize="rows"
  height={500}
  virtualScrollConfig={{
    overscan: 10,
    estimateSize: () => 48,
  }}
  columns={columns}
/>
```

## Infinite scroll

Use the `onScrollToBottom` callback to load more data when the user scrolls near the bottom of the grid.
This works with or without virtualization. Combine with `loading` and `loadingVariant="bar"` to show
progress without hiding the rows that are already loaded.

## Column virtualization

Set `virtualize="columns"` to enable column virtualization when working with 50 or more columns.
Only the columns visible in the horizontal scroll area are rendered to the DOM. Fine-tune behavior
with the `virtualColumnConfig` option:

```tsx
<DataGrid
  store={store}
  virtualize="columns"
  height={500}
  virtualColumnConfig={{
    overscan: 5,
    estimateSize: (index) => columns[index]?.size ?? 150,
  }}
/>
```

Combine row and column virtualization with `virtualize="rows,columns"` for grids with many rows
and many columns simultaneously.

## Parity with the table body

The virtualized body renders `div` elements with ARIA grid roles instead of a `<table>`, but every
look and behavior is keyed on the same data attributes, so it matches the table body: sort
indicators and the header chrome (column menu, resize handles, reorder), utility columns as real
cells, row selection and the row focus model, cell selection, group rows, tree rows, expansion
panels, editing in both modes, the empty state, the three loading variants, pinned columns with the
divider and shadow, and the chrome (toolbar, selection bar, footer, totals row). The header of a
virtualized grid is always sticky at the top of its scroll container.

Row pinning and row reorder are turned off with a development warning under any `virtualize`
value. Virtualized rendering positions each cell independently, which is why cell spanning
(`spanRows` / `spanColumns`) is not applied. The virtualized body scrolls inside its own container,
so `withScrollArea` and `stickyHeaderOffset` do not apply to it.

## Performance tips

- Always memoize your `data` and `columns` arrays with `useMemo` to prevent unnecessary re-renders.
- Set explicit `size` on columns to avoid layout recalculation.
- Use `getRowId` to provide stable row identifiers instead of relying on array index.
- Adjust `overscan` based on row height -- fewer overscan rows for tall rows, more for short rows.
- For extremely large datasets (1M+ rows), consider server-side pagination instead.

## Accessibility

Virtualized grids maintain ARIA grid semantics. DataGrid sets `role="grid"` with `aria-rowcount` on
the container, `role="row"` with `aria-rowindex` on each row, and `role="gridcell"` /
`role="columnheader"` with `aria-colindex` on cells, so screen readers announce the row position
(for example "row 500 of 100,000") even though only a window of rows is in the DOM. Keyboard
navigation follows the same focus model as the table body, see
[Accessibility](/data-grid/accessibility).
