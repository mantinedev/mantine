## virtualize prop

The `virtualize` prop controls which axis is virtualized. Pass one of the following values:

```tsx
<DataGrid store={store} virtualize="rows" height={500} />
<DataGrid store={store} virtualize="columns" height={500} />
<DataGrid store={store} virtualize="rows,columns" height={500} />
```

The `height` prop is required for all virtualization modes so the grid has a bounded scroll container.

## Row height estimate

The virtualized body needs an estimated height per row before it measures the rendered rows. The
estimate is resolved in this order, first hit wins:

1. `virtualScrollConfig.estimateSize(index)`
2. `getRowHeight(row)` when it returns a number
3. `estimateRowHeight`
4. the row height of the current grid `size` (`32px` at `sm`)

If `getRowHeight` returns a number, it is the rendered height of the row. Return `'auto'`
for rows with wrapped content (for example with `textOverflow="wrap"`): such rows are measured
after render and grow to fit their content.

## Virtual scroll config

Fine-tune virtual scroll behavior with the `virtualScrollConfig` prop:

- `overscan` – number of rows rendered above and below the visible area, `10` by default
- `estimateSize` – function that returns the estimated row height in px

```tsx
<DataGrid
  data={data}
  virtualize="rows"
  height={500}
  virtualScrollConfig={{
    overscan: 10,
    estimateSize: () => 48,
  }}
  columns={columns}
/>
```

## Infinite scroll

Use the `onScrollToBottom` callback to load more data when the user scrolls near the bottom of the grid.
It works with or without virtualization. Combine it with `loading` and `loadingVariant="bar"` to show
progress without hiding the rows that are already loaded.

## Column virtualization

Set `virtualize="columns"` to render only the columns visible in the horizontal scroll area.
Use it for grids with 50 or more columns. Fine-tune behavior with the `virtualColumnConfig` prop:

```tsx
<DataGrid
  store={store}
  virtualize="columns"
  height={500}
  virtualColumnConfig={{
    overscan: 5,
    estimateSize: (index) => columns[index]?.size ?? 150,
  }}
/>
```

Set `virtualize="rows,columns"` for grids with many rows and many columns.

## Parity with the table body

The virtualized body renders `div` elements with ARIA grid roles instead of a `<table>`.
It looks and behaves like the table body, see the table below for the features that are not supported.
The header of a virtualized grid is always sticky.

## Performance tips

- Always memoize your `data` and `columns` arrays with `useMemo` to prevent unnecessary re-renders.
- Set explicit `size` on columns to avoid layout recalculation.
- Use `getRowId` to provide stable row identifiers instead of relying on array index.
- Adjust `overscan` based on row height: fewer overscan rows for tall rows, more for short rows.
- For extremely large datasets (1M+ rows), consider server-side pagination instead.

## Accessibility

The virtualized grid sets `aria-rowcount`, `aria-rowindex` and `aria-colindex`, so screen readers
announce the row position (for example "row 500 of 100,000") even though only a part of the rows
is in the DOM. Keyboard navigation follows the same focus model as the table body, see
[Accessibility](/data-grid/accessibility).
