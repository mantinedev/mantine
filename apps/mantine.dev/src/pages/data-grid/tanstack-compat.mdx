## TanStack Table version

DataGrid is built on [TanStack Table v9](https://tanstack.com/table/latest). The v9 packages are
peer dependencies, so your application controls the exact version:

```bash
yarn add @tanstack/react-table @tanstack/match-sorter-utils
```

## Bound types

TanStack Table v9 types take the registered feature set as their first generic argument. DataGrid
exports aliases that are already bound to its feature set, so you never have to pass it yourself:

<DataTable
  head={['DataGrid alias', 'TanStack equivalent']}
  data={[
    ['`DataGridColumnDef<TData>`', '`ColumnDef<DataGridFeatures, TData>`'],
    ['`DataGridTable<TData>`', '`Table<DataGridFeatures, TData>`'],
    ['`DataGridRow<TData>`', '`Row<DataGridFeatures, TData>`'],
    ['`DataGridCell<TData>`', '`Cell<DataGridFeatures, TData>`'],
    ['`DataGridColumn<TData>`', '`Column<DataGridFeatures, TData>`'],
    ['`DataGridFilterFn<TData>`', '`FilterFn<DataGridFeatures, TData>`'],
    ['`DataGridSortFn<TData>`', '`SortFn<DataGridFeatures, TData>`'],
  ]}
/>

```tsx
import { DataGridColumnDef, DataGridFilterFn } from '@mantine/data-grid';

const columns: DataGridColumnDef<Person>[] = [{ accessorKey: 'name', header: 'Name' }];

const exactMatch: DataGridFilterFn = (row, columnId, filterValue) =>
  String(row.getValue(columnId)) === filterValue;
```

The registered feature set itself is exported as `dataGridFeatures` (value) and `DataGridFeatures`
(type) if you need to build TanStack types by hand.

## Features and row models

In v9 features and row models are registered explicitly rather than passed as `getXRowModel`
options. DataGrid does this for you: it registers the full feature set and enables only the row
models the grid actually needs, based on the props you pass to `useDataGrid`.

This matters because `table.getRowModel()` resolves to the paginated row model. DataGrid only
registers the paginated row model when the grid is actually paginated, so an unpaginated grid keeps
rendering all of its rows.

## Using tableOptions

Any TanStack Table option not directly exposed by `useDataGrid` can be passed through `tableOptions`:

```tsx
const store = useDataGrid({
  data,
  columns,
  tableOptions: {
    enableMultiSort: true,
    maxMultiSortColCount: 3,
    sortDescFirst: false,
    debugTable: process.env.NODE_ENV === 'development',
  },
});
```

This provides a full escape hatch to the underlying TanStack Table instance without losing
the DataGrid features built on top.

## Accessing table state

TanStack Table v9 replaced `table.getState()` with a store. Read state from `table.store.state`, or
subscribe to a single slice with `table.atoms`:

```tsx
const store = useDataGrid({ data, columns });

store.table.store.state.sorting;
store.table.atoms.sorting.get();
```

Commonly used slices are also mirrored on the DataGrid store directly (`store.sorting`,
`store.pagination`, `store.rowSelection` and so on).

## Module format

TanStack Table v9 is published as ES modules only. Bundlers such as Vite, webpack and Next.js handle
this transparently. If you consume DataGrid from CommonJS with a raw `require()`, you need Node
22.12 or newer (or 20.19+), where `require()` of an ES module is supported.
