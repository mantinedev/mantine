## Usage

The `TimePicker` component is an alternative to [TimeInput](/dates/time-input) that offers more
features. It supports 24-hour and 12-hour formats, a dropdown with hours, minutes and seconds, and
more.

<Demo data={TimePickerDemos.usage} />

## Controlled

The `TimePicker` component value is a string in `hh:mm:ss` or `hh:mm` 24-hour format (for example `18:34:55`).
An empty string is used to represent no value. The `onChange` function is called only when the entered value is valid.
The input value is considered valid in the following cases:

- All inputs are empty. In this case, `onChange` is called with an empty string.
- All inputs are filled. For example, if the `withSeconds` prop is set and the user entered `12:34:56`, `onChange` will be called with `12:34:56`. But if the user entered `12:34`, `onChange` will not be called because the seconds value is missing.

```tsx
import { useState } from 'react';
import { TimePicker } from '@mantine/dates';

function Demo() {
  const [value, setValue] = useState('');
  return <TimePicker value={value} onChange={setValue} />;
}
```

## Controlling with useTimePicker

`value`/`defaultValue`/`onChange` report only complete values: while the user is halfway through
entering a time, `onChange` is called with an empty string, so from the outside every incomplete
state looks the same. Create a controller with the `useTimePicker` hook and pass it to `TimePicker`
with the `controller` prop to read the individual fields, move focus between them and set or clear
the value from anywhere in your application. The [Controllers](/guides/controllers) guide covers how
the pattern works across all components:

<Demo data={TimePickerDemos.controller} />

`useTimePicker` accepts the state options that `TimePicker` accepts as props, and returns the
current state, actions and queries:

```tsx
import { TimePicker, useTimePicker } from '@mantine/dates';

function Demo() {
  const timePicker = useTimePicker({
    defaultValue: '12:30', // -> uncontrolled initial value
    // value, onChange -> controlled state, same as on TimePicker
    // type, format, amPmLabels, withSeconds, min, max, pasteSplit -> same as on TimePicker
  });

  // Actions
  timePicker.setValue('14:30:00'); // -> sets all fields from a time string
  timePicker.setHours(14);
  timePicker.setMinutes(30);
  timePicker.setSeconds(0);
  timePicker.setAmPm('PM');
  timePicker.clear(); // -> clears all fields and focuses the hours field
  timePicker.clamp(); // -> clamps the current value to min and max
  timePicker.focus('minutes'); // -> 'hours' | 'minutes' | 'seconds' | 'amPm'

  // Queries
  timePicker.getValue(); // -> current value in hh:mm:ss or hh:mm 24h format, '' if it is not complete
  timePicker.getHours(); // -> number | null
  timePicker.getMinutes(); // -> number | null
  timePicker.getSeconds(); // -> number | null
  timePicker.getAmPm(); // -> string | null, always null in 24h format
  timePicker.hasValue(); // -> boolean, true if at least one field has a value

  return <TimePicker controller={timePicker} />;
}
```

The controller owns the state, so when the `controller` prop is set, the `value`, `defaultValue`,
`onChange`, `type`, `format`, `amPmLabels`, `withSeconds`, `min`, `max` and `pasteSplit` props of
`TimePicker` are ignored – pass them to `useTimePicker` instead. `type`, `format`, `withSeconds` and
`amPmLabels` also decide which fields are rendered, so a controller created with `format: '12h'`
renders the am/pm field even if the component is left with the default `format` prop.

Options that reach `TimePicker` through `theme.components.TimePicker.defaultProps` do not reach a
controller you create yourself – pass them to `useTimePicker` as well.

`focus` is a no-op until a `TimePicker` is mounted with the controller, because it works on the
fields that component renders.

The controller is typed as `TimePickerController` and its options as `TimePickerControllerOptions`,
both exported from `@mantine/dates`.

## With seconds

Set the `withSeconds` prop to enable seconds input. Note that if this prop is used,
`onChange` is not called until all inputs are filled – it is not possible
to enter only hours and minutes.

<Demo data={TimePickerDemos.withSeconds} />

## Duration type

Set `type="duration"` to allow entering durations that exceed 24 hours.
In this mode, the hours field has no upper limit and the input width adjusts
dynamically based on the entered value. The `format` prop is ignored (always 24h)
and the dropdown is disabled.

<Demo data={TimePickerDemos.duration} />

## Min hours digits

Use the `minHoursDigits` prop to set the minimum number of digits displayed in the hours input.
This prop is only applicable when `type="duration"` is set. By default, the minimum is `2`.

<Demo data={TimePickerDemos.minHoursDigits} />

## 12-hour format

## Time presets

You can define time presets with `presets` prop. Presets are displayed in the dropdown and can be selected by clicking on them.
Time values for presets should be in `hh:mm:ss` or `hh:mm` 24-hour time format. Presets
display value is generated based on `format`, `amPmLabels` and `withSeconds` props.

By default, the dropdown is displayed below the input if there is enough space; otherwise it is displayed above the input.
You can change this behavior by setting `position` and `middlewares` props, which are passed down to the
underlying [Popover](/core/popover) component.

## Get refs of inner inputs

Use `hoursRef`, `minutesRef`, `secondsRef` and `amPmRef` props to get refs of inner inputs:

```tsx
import { useRef } from 'react';
import { TimePicker } from '@mantine/dates';

function Demo() {
  const hoursRef = useRef<HTMLInputElement>(null);
  const minutesRef = useRef<HTMLInputElement>(null);
  const secondsRef = useRef<HTMLInputElement>(null);
  const amPmRef = useRef<HTMLSelectElement>(null);

  return (
    <TimePicker
      hoursRef={hoursRef}
      minutesRef={minutesRef}
      secondsRef={secondsRef}
      amPmRef={amPmRef}
    />
  );
}
```

## onFocus and onBlur events

`onFocus` and `onBlur` events are called when the first input is focused and the last input is blurred:

```tsx
import { TimePicker } from '@mantine/dates';

function Demo() {
  return (
    <TimePicker
      onFocus={() => console.log('Focused')}
      onBlur={() => console.log('Blurred')}
    />
  );
}
```

## Accessibility

Set aria labels for hours, minutes, seconds and am/pm inputs and clear button with corresponding props:

```tsx
import { TimePicker } from '@mantine/dates';

function Demo() {
  return (
    <TimePicker
      hoursInputLabel="Hours"
      minutesInputLabel="Minutes"
      secondsInputLabel="Seconds"
      amPmInputLabel="AM/PM"
      clearButtonProps={{ 'aria-label': 'Clear time' }}
    />
  );
}
```
