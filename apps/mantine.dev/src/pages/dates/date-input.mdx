## Value format

Use the `valueFormat` prop to change the [dayjs format](https://day.js.org/docs/en/display/format) of the value label.
To use some custom formats, you need to enable the [custom parse format](https://day.js.org/docs/en/plugin/custom-parse-format) plugin:

```tsx
// Do this once in your application root file
import dayjs from 'dayjs';
import customParseFormat from 'dayjs/plugin/customParseFormat';

dayjs.extend(customParseFormat);
```

Example of using DateInput with a custom format:

<Demo data={DateInputDemos.format} />

`valueFormat` also accepts a function that receives the value as a `YYYY-MM-DD` string and returns
the formatted value. Use it to format the value with
[Intl.DateTimeFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat)
instead of dayjs – see [formatting without dayjs](/dates/getting-started/#formatting-without-dayjs).

Note that `valueFormat` is also used to parse user input – a function cannot be used for that.
When `valueFormat` is a function, typed values are parsed as `YYYY-MM-DD` strings.
Set the `dateParser` prop to support other formats:

```tsx
import { DateInput } from '@mantine/dates';

function Demo() {
  return (
    <DateInput
      valueFormat={(date) =>
        new Intl.DateTimeFormat('en-US', { dateStyle: 'long' }).format(new Date(`${date}T00:00:00`))
      }
      dateParser={(input) => {
        const parsed = new Date(input);
        return Number.isNaN(parsed.getTime()) ? null : parsed;
      }}
    />
  );
}
```

## With time

If your `valueFormat` includes time (for example, `YYYY-MM-DD HH:mm`), set the `withTime` prop
to preserve the time part of the value. Without `withTime`, the time portion is discarded and
always defaults to `00:00`:

<Demo data={DateInputDemos.time} />

## Date parser

Use the `dateParser` prop to replace the default date parser. The parser function accepts user input (string)
and returns a `YYYY-MM-DD` date string (`YYYY-MM-DD HH:mm:ss` with `withTime`) or `null` if the input cannot be parsed. A `Date` object is also accepted:

<Demo data={DateInputDemos.parser} />

## Min and max date

Set the `minDate` and `maxDate` props to define minimum and maximum dates. If a date that is after `maxDate`
or before `minDate` is entered, it will be considered invalid and the input value will be reverted
to the last known valid date value.

## Controlling with useDateInput

`DateInput` component supports the [controller pattern](/guides/controllers). Use the `useDateInput` hook to manage `DateInput` state:

<Demo data={DateInputDemos.controller} />

`useDateInput` returns the dropdown actions together with the navigation actions of
[useCalendar](/dates/calendar/#controlling-with-usecalendar):

```tsx
import { useState } from 'react';
import { DateInput, useDateInput } from '@mantine/dates';

function Demo() {
  const [value, setValue] = useState<string | null>(null);
  const controller = useDateInput({
    defaultLevel: 'month', // -> level the dropdown opens on
    defaultDate: '2024-06-15', // -> date the dropdown displays first
    // dropdownOpened, defaultDropdownOpened, onDropdownOpenedChange -> dropdown state
    // date, onDateChange, level, onLevelChange -> same as on useCalendar
  });

  // Dropdown actions
  controller.openDropdown();
  controller.closeDropdown();
  controller.toggleDropdown();

  // Navigation actions, same as useCalendar
  controller.setLevel('year');
  controller.setDate('2024-08-01');
  controller.next();
  controller.previous();

  // Queries
  controller.isDropdownOpened(); // -> true | false
  controller.getDate(); // -> displayed date
  controller.getLevel(); // -> 'month' | 'year' | 'decade'
  controller.getDisplayedDate(); // -> the date the dropdown displays
  controller.getDisplayedLevel(); // -> level clamped to minLevel/maxLevel

  return <DateInput value={value} onChange={setValue} controller={controller} />;
}
```

The controller does not own the selected value or the typed text – keep using `value`/`onChange`
(or your form library) for it. When the `controller` prop is set, the `date`, `defaultDate`,
`onDateChange`, `level`, `defaultLevel` and `onLevelChange` props are ignored – pass them to
`useDateInput` instead.

Every time the dropdown opens, the level is reset to `defaultLevel`, the same as without a controller.
The displayed date is kept between opens: it follows the typed or controlled value and stays on the
month the user navigated to. When the controller has no displayed date yet, the dropdown opens on the
month of the value. To open on a different level or date, call `setLevel` or `setDate` right after
`openDropdown`, as the demo above does. A controlled `level` is not reset.

`openDropdown` does nothing while the input is `disabled` or `readOnly`. Do not combine the controller
with `popoverProps.opened`, which overrides the dropdown state the controller owns.

The controller is typed as `PickerInputController` and its options as `PickerInputControllerOptions`,
both exported from `@mantine/dates`, the same types as the
[DatePickerInput](/dates/date-picker-input/#controlling-with-usedatepickerinput) controller.
