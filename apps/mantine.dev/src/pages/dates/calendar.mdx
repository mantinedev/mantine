## Usage

Use the `Calendar` component to create custom date pickers if the [DatePicker](/dates/date-picker/)
component does not meet your requirements. `Calendar` supports all [DatePicker](/dates/date-picker/)
props and some additional props that are listed in the props table – check it out to learn about all component features.

By default, `Calendar` works the same way as the [DatePicker](/dates/date-picker/) component but does not
include any logic for date selection:

## Controlling with useCalendar

`Calendar` manages the displayed date and level on its own, and the
`date`/`defaultDate`/`onDateChange` and `level`/`defaultLevel`/`onLevelChange` props are enough for
most cases. When you need to drive the calendar from outside – from a toolbar, a keyboard shortcut
or another component – create a controller with the `useCalendar` hook and pass it to `Calendar`
with the `controller` prop. The controller exposes actions that props cannot express, for example
stepping the displayed period with the same `columnsToScroll` the component uses and setting the
level with the component's own `minLevel`/`maxLevel` clamping. The
[Controllers](/guides/controllers) guide covers how the pattern works across all components:

<Demo data={CalendarDemos.controller} />

`useCalendar` accepts the state options that `Calendar` accepts as props, and returns the current
state, actions and queries:

```tsx
import { Calendar, useCalendar } from '@mantine/dates';

function Demo() {
  const calendar = useCalendar({
    defaultDate: '2024-06-15', // -> uncontrolled initial displayed date
    defaultLevel: 'month', // -> uncontrolled initial displayed level
    // date, onDateChange -> controlled displayed date, same as on Calendar
    // level, onLevelChange -> controlled displayed level, same as on Calendar
  });

  // Actions
  calendar.setDate('2024-08-01'); // -> also accepts a Date object
  calendar.setLevel('year'); // -> clamped to minLevel/maxLevel of the Calendar
  calendar.next(); // -> steps forward by the current level
  calendar.previous();
  calendar.nextMonth(); // -> also nextYear, nextDecade
  calendar.previousMonth(); // -> also previousYear, previousDecade

  // Queries
  calendar.getDate(); // -> displayed date, null until it is set
  calendar.getLevel(); // -> 'month' | 'year' | 'decade'
  calendar.getDisplayedDate(); // -> the date the Calendar displays, falls back when date is null
  calendar.getDisplayedLevel(); // -> level clamped to minLevel/maxLevel of the Calendar

  return <Calendar controller={calendar} />;
}
```

The controller owns the displayed date and level, so when the `controller` prop is set, the `date`,
`defaultDate`, `onDateChange`, `level`, `defaultLevel` and `onLevelChange` props of `Calendar` are
ignored – pass them to `useCalendar` instead. Every other prop, including `minLevel`, `maxLevel`,
`minDate`, `maxDate`, `numberOfColumns` and `columnsToScroll`, stays on the component.

The stepping actions and `getDisplayedDate` depend on values that only a mounted `Calendar` knows –
the resolved `columnsToScroll`, the `minLevel`/`maxLevel` clamping and the date the calendar falls
back to when `date` is `null`. They are no-ops and return `null` until a `Calendar` with the
controller is rendered.

The controller is typed as `CalendarController` and its options as `CalendarControllerOptions`, both
exported from `@mantine/dates`.
